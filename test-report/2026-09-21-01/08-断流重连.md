# 08 · 断流重连线(L8)

- 业务线:SDK 流式中途断流 → 自动重连 → 续流/收敛(2 用例,2 通过,其中 1 例为 DEF-06 确定性取证)
- spec:`e2e/specs/09-stream-reconnect.spec.ts`
- 手段(任务口径「再包一层 e2e 断点代理」):`e2e/reconnect-host.mjs` 在独立端口 18085 同源托管 WC 宿主页 + `/ia` 反代 18090,提供 `POST /__break?seconds=N`(立刻销毁全部活动 socket + N 秒内拒绝新连接,模拟物理断链;支持 `allow=running` 白名单放行元信息面,用于 DEF-06 确定性取证)。事件逐行落日志: `[cut]`(销毁)、`[reconn]`(SDK 重连游标 Last-Event-ID)、`[drop]/[pass]`。

## SDK 重连机制(源码口径,store/assistant.ts)

流错误 → `onError` → `scheduleEnsureRetry(5s)` → `ensureContentConnection` → 若 `statusConfirmed && knownRunId` 直接 `connect('reconnect')` → `GET /runs/{id}/events`(Last-Event-ID=runId:seq)从游标后重放。并行存在 1s 级状态轮询(`/runs/running`),run 一旦完成即把会话判「已完成」并使后续重连放弃。

## L8-01 · 流式中途断流 → 自动恢复 → UI 终态收敛与数据完整

- 步骤:发送消息 → 首段内容增量渲染后触发 2s 断流(销毁 SSE 连接)→ 记录断流中 UI 状态 → 代理恢复 → 等待收敛;断言终态、无残留错误态、psql 事件 seq 连续、库层助手消息全文;若走到「自动重连续流」路径,追加重连游标与重放连续性断言。
- 期望:断流后无需人工干预,UI 收敛「已完成」且数据完整;重连时 Last-Event-ID 续传真确。
- 实际(路径 A,自动重连续流):断流中 UI 瞬时出现错误条「network error + 重试」;约 5s 后 SDK 自动重连(日志 `[reconn] Last-Event-ID=…:12`),重放 `13→…→21` 直达 DONE,UI 续流至全文(内容长度 10→127),错误条自动清除,终态「已完成」;重放事件与库内「游标之后全部可见事件」逐一对齐;`ia_agent_run.status=COMPLETED`。
- 判定:✅ 通过(路径 A;若竞态落入路径 B 则转 DEF-06 取证,L8-06 已单列确定性取证)

## L8-06 · DEF 取证:长断流覆盖 run 终态 → UI「已完成」但内容截断(DEF-06)

- 步骤:发送后等首个内容增量,触发 8s 断流(`allow=running` 白名单放行 `/runs/running`,使轮询面存活 → 确定性),覆盖 run 终态(legacy run ~6s);恢复后观察 UI 终态与内容,并对照库层助手消息全文;再刷新页面验证历史回放。
- 期望(PRD/契约):断流恢复后 UI 应与持久层一致(全文),或自动补偿拉取。
- 实际:断流窗口内 run 完成,轮询判「已完成」→ SDK 放弃重连;UI 终态「已完成」但消息区只有断流前缀(`[mock] 你好,`),**缺失全部后续内容**;库层 `ia_agent_message` 为全文(含收尾段);刷新页面后历史回放恢复全文。UI 与持久层不一致即为缺陷本体。
- 判定:❌ 缺陷取证 → **DEF-06(P2)**
- 证据:`L8-07-长断流中-UI状态.png`、`L8-08-DEF06-已完成但内容截断.png`、`L8-08-DEF06-取证.json`(uiMissingFooter=true / dbHasFooter=true)、`L8-09-DEF06-刷新后历史回放全文.png`

## 本线结论

| # | 用例 | 判定 |
| --- | --- | --- |
| L8-01 | 断流→自动恢复→收敛与数据完整 | ✅(路径 A 实证) |
| L8-06 | 断流覆盖终态→截断 | ❌ DEF-06 取证 |

- 手段说明:任务口径要求的「UI 层断流」经由可断中转在真实浏览器网络层注入(非 mock fetch),SDK 走原生 fetch→错误→重连全链路;事件 seq 连续性以「库内可见事件」与「UI 端 SSE 捕获/重放响应体」双侧对齐佐证。
- 修复意见(DEF-06,详见分册):轮询判「已完成」时若本地 `lastSequence < 服务端 lastSequence`,应拉取历史/补偿 `/events` 合并转录,不得保留截断的 live 投影;或完成态保留一次补偿性重连。
- 修复意见(F12,观察项):断流中 UI 瞬时暴露原始错误文案「network error」+「重试」按钮(重连成功后自动清除),建议改为「连接中断,自动重连中…」静默提示。
