## 1. 架构一页图(文字版)

InnerAgent 是**只服务宿主应用的内嵌智能体微服务**。一次接入涉及三个角色:

```text
┌─────────────────────────── 宿主应用 ───────────────────────────┐
│                                                                │
│  ┌─ 宿主前端(业务页面)──────────────┐   ┌─ 宿主后端 ────────┐ │
│  │ @inneragent/sdk                    │   │ ① embed token 签发 │ │
│  │  init({appKey, tokenGetter})       │   │    (RS256 私钥在本 │ │
│  │  <inneragent-chat> Web Component   │   │     方,公钥登记给  │ │
│  │  setAssistantPageContext(页/对象)  │   │     InnerAgent)    │ │
│  └───────────────┬────────────────────┘   │ ② 业务工具实现      │ │
│                  │ Authorization: Bearer   │    (@IaTool 方法)  │ │
│                  │  embed token            │ ③ act 验签 Filter  │ │
│                  ▼                         │    + /ia-mcp 桥    │ │
│  ┌──────────────────────────────────────────────────────────┐ │ │
│  │ inneragent-spring-boot-starter(宿主进程内)               │ │ │
│  │  · 扫描 @IaTool → 注册进进程内 MCP server(/ia-mcp 端点)  │ │ │
│  │  · IaActTokenFilter:验 X-IA-Act → 重建用户上下文         │ │ │
│  └──────────────────────────────────────────────────────────┘ │ │
└───────────────┬───────────────────────────────────▲────────────┘
                │ embed token 验签                   │ X-IA-Act(act token,
                ▼                                   │  每 tools/call 新签,60s)
┌─────────────────── InnerAgent server ────────────┴────────────┐
│  · 运行内核(SSE 流式、确认流、白名单/授权判定)               │
│  · 管理面 /ia/api/v1/admin/**(应用/工具/授权/熔断/审计)      │
│  · MCP 客户端:按 (appId, endpoint_url) 懒连宿主桥,          │
│    每次 tools/call 签发 act token(aud=endpoint_url)          │
└────────────────────────────────────────────────────────────────┘
```

**双级令牌流向**(详见 §4):

| 令牌 | 签发方 | 传输头 | 消费方 | 有效期 |
| --- | --- | --- | --- | --- |
| **embed token** | 宿主后端(私钥签 RS256;公钥在管理面登记) | `Authorization: Bearer <jwt>` | InnerAgent server 验签(公钥 + 轮换宽限旧钥) | 宿主自定 `exp`(服务端建议 12h) |
| **act token** | InnerAgent server(每次 MCP `tools/call` 现签) | `X-IA-Act`(不占用 `Authorization`) | 宿主桥 `IaActTokenFilter` 验签(JWKS + kid),工具方法以 `IaActClaims` 拿到身份 | 60s |

act token **只在宿主桥内环**:InnerAgent → 宿主 `/ia-mcp` 的机器调用;绝不透传给三方 MCP(三方走规范 OAuth 或静态头)。

## 2. 快速开始(五步)

前置:InnerAgent server 已部署并起在 `http://localhost:18090`(本指南端口基准);宿主为 Spring Boot Servlet Web 应用(Java 21)。

### 步骤 ① 引依赖

```xml
<dependency>
    <groupId>com.inneragent</groupId>
    <artifactId>inneragent-spring-boot-starter</artifactId>
    <version>0.1.0-SNAPSHOT</version>
</dependency>
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
</dependency>
```

starter 经 `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` 自动装配(`inneragent-starter/src/main/resources/META-INF/spring/...`),条件为 Servlet Web 应用且 `inneragent.bridge.enabled=true`(默认 true)——宿主**无需任何 `@EnableXxx` 注解**(出处:`inneragent-starter/src/main/java/com/inneragent/starter/config/IaBridgeAutoConfiguration.java`)。

> 注意:工具方法参数名依赖 `-parameters` 编译参数(starter 模块构建已开启;宿主若在自己的模块里写工具,请确认该模块也开启,或一律显式写 `@IaToolParam(value="...")`,见步骤 ②)。出处:`inneragent-starter/src/main/java/com/inneragent/starter/IaToolSchemas.java`(缺参即抛「参数名不可得」)。

### 步骤 ② 写工具(@IaTool / @IaToolParam)

注解定义(出处:`inneragent-starter/src/main/java/com/inneragent/starter/IaTool.java`、`IaToolParam.java`):

| 注解属性 | 说明 | 缺省 |
| --- | --- | --- |
| `@IaTool.name` | MCP 工具名(桥内唯一) | 方法名 |
| `@IaTool.description` | 模型可见描述 | 工具名 |
| `@IaTool.riskLevel` | `READ` / `WRITE` / `DESTRUCTIVE`(出处:`starter/ToolRiskLevel.java`) | `WRITE` |
| `@IaToolParam.value` | 参数名 | 反射参数名(需 `-parameters`) |
| `@IaToolParam.description` | 参数描述(进 schema) | 无 |
| `@IaToolParam.required` | 是否进 schema `required` 数组 | `true`(保守默认) |

完整可编译示例——一读一写(直接可用;`records` 换成你的业务 Service):

```java
package com.example.host.tool;

import com.inneragent.starter.IaActClaims;
import com.inneragent.starter.IaTool;
import com.inneragent.starter.IaToolParam;
import com.inneragent.starter.ToolRiskLevel;
import org.springframework.stereotype.Component;

import java.util.LinkedHashMap;
import java.util.Map;
import java.util.concurrent.ConcurrentHashMap;

/** 宿主 CRM 工具。@Component 形态:starter 自动扫描所有 bean 的 @IaTool 方法。 */
@Component
public class CrmTools {

    private final Map<String, Map<String, Object>> records = new ConcurrentHashMap<>();

    /** 读工具:READ → readOnlyHint=true,DEFAULT 档位自动执行、不打扰用户。 */
    @IaTool(name = "get_customer",
            description = "按客户 ID 查询客户姓名、等级与负责人",
            riskLevel = ToolRiskLevel.READ)
    public Map<String, Object> getCustomer(
            @IaToolParam(value = "customer_id", description = "客户唯一 ID,形如 CUST-1001") String customerId,
            IaActClaims claims) {                       // 尾参注入验签后的 act 身份(可省)
        Map<String, Object> record = records.get(customerId);
        Map<String, Object> result = new LinkedHashMap<>();
        if (record == null) {
            result.put("status", "error");
            result.put("message", "客户 " + customerId + " 不存在,未做任何修改;请确认 ID 后重试");
            return result;                              // 平台 status 契约:错误回灌模型、可续跑
        }
        result.put("status", "ok");
        result.put("customerId", customerId);
        result.put("name", record.get("name"));
        result.put("level", record.get("level"));
        result.put("queriedBy", claims.userId());       // act token 重建的终端用户身份
        return result;
    }

    /** 写工具:WRITE → DEFAULT 档位需用户在确认卡批准;批准时可勾「总是允许」。 */
    @IaTool(name = "update_customer_level",
            description = "修改客户等级(level ∈ normal/silver/gold)",
            riskLevel = ToolRiskLevel.WRITE)
    public Map<String, Object> updateCustomerLevel(
            @IaToolParam(value = "customer_id", description = "客户唯一 ID") String customerId,
            @IaToolParam(value = "level", description = "目标等级:normal/silver/gold") String level,
            IaActClaims claims) {
        Map<String, Object> record = records.get(customerId);
        Map<String, Object> result = new LinkedHashMap<>();
        if (record == null) {
            result.put("status", "error");
            result.put("message", "客户 " + customerId + " 不存在,记录未被修改");
            return result;                              // 拒绝文案必须陈述后果
        }
        record.put("level", level);                     // 宿主侧做最终权限校验(ADR-3)
        result.put("status", "ok");
        result.put("customerId", customerId);
        result.put("level", level);
        result.put("updatedBy", claims.userId());
        result.put("runId", claims.runId());
        return result;
    }
}
```

风险级与确认的关系(运行时由 InnerAgent 判定,详见《工具设计规范》§4):

- `READ` → 注解 `readOnlyHint=true` → DEFAULT 档**自动执行**;
- `WRITE` → DEFAULT 档**先确认后执行**;用户在确认卡选「总是允许(该工具)」后形成 `permanent` 授权,之后免确认;选「本会话允许」形成 `conversation` 授权;
- `DESTRUCTIVE` → `destructiveHint=true` → 注册时强制高风险(LOW/MEDIUM/HIGH 的 `HIGH`),一律确认。

工具方法的返回与异常映射(出处:`inneragent-starter/src/main/java/com/inneragent/starter/IaToolInvoker.java`):返回 `Map` 原样进 `structuredContent`;抛任意异常 → `isError=true` + `{"status":"error","message":...}` 回灌模型(运行不终止)。

### 步骤 ③ yaml 最小配置

`application.yml`:

```yaml
inneragent:
  bridge:
    # InnerAgent 主服务地址(宿主从这里拉 JWKS 验 act token)
    server-base: http://localhost:18090
    # 工具类所在包(非 bean 形态工具;上面 @Component 示例可不配)
    tool-packages:
      - com.example.host.tool
    act:
      # 【最关键的一行】期望的 act token aud,必须包含「步骤④注册工具时写的
      # endpoint_url」。starter 默认占位值 ia-mcp 不作数,错配即 /ia-mcp 全量 401。
      audiences:
        - http://localhost:18091/ia-mcp
```

配置键全集(前缀 `inneragent.bridge`,出处:`inneragent-starter/src/main/java/com/inneragent/starter/config/IaBridgeProperties.java`):

| 键 | 缺省 | 说明 |
| --- | --- | --- |
| `inneragent.bridge.enabled` | `true` | false = 不装配桥 |
| `inneragent.bridge.server-base` | 无 | 主服务地址;未配置启动仅 WARN,但 `/ia-mcp` 因 JWKS 不可达全量 401(fail-closed) |
| `inneragent.bridge.endpoint` | `/ia-mcp` | 宿主桥 MCP 端点路径(无状态 servlet) |
| `inneragent.bridge.server-name` | `inneragent-host-bridge` | MCP serverInfo 名 |
| `inneragent.bridge.tool-packages` | 空 | 非 bean 工具类的扫描包 |
| `inneragent.bridge.scan.fail-fast` | `true` | 工具重名/schema 失败是否阻断启动 |
| `inneragent.bridge.act.jwks-path` | `/.well-known/jwks.json` | 拼在 server-base 后 |
| `inneragent.bridge.act.cache-ttl` | `5m` | JWKS 周期刷新 |
| `inneragent.bridge.act.key-retention` | `72h` | JWKS 中消失密钥的本地保留期(轮换宽限) |
| `inneragent.bridge.act.forced-refresh-cooldown` | `5s` | 未知 kid 强刷节流 |
| `inneragent.bridge.act.issuer` | `inneragent` | 期望 `iss` |
| `inneragent.bridge.act.audiences` | `[ia-mcp]`(占位) | 期望 `aud` 列表,**必须改** |
| `inneragent.bridge.act.clock-skew` | `30s` | exp/nbf 容忍偏移 |

**本步常见错误(默认占位 ia-mcp 不匹配)**:`act.audiences` 不改,或与注册到管理面的 `endpoint_url` 不一致。InnerAgent 按 `ia_tool_registry.endpoint_url` 签发 act token 的 `aud`(出处:`inneragent-server/src/main/java/com/inneragent/agent/mcp/McpClientToolInvoker.java`),宿主 Filter 做 audience 精确匹配,不匹配统一 401 `{"error":"invalid_act_token"}` 且不区分失败细节(出处:`inneragent-starter/src/main/java/com/inneragent/starter/act/IaActTokenFilter.java`)。**排障口诀:先对齐「yaml audiences = 管理面 endpoint_url」,再查别的。**

### 步骤 ④ 管理面注册应用 + 注册工具 + 授权

管理面鉴权双轨(出处:`inneragent-server/src/main/java/com/inneragent/server/admin/AdminTokenFilter.java`):

- 自动化/脚本:请求头 `X-IA-Admin-Key: <IA_ADMIN_KEY 环境变量值>`(服务端未配置该环境变量时管理面整体 403 默认关闭);
- 人工登录:`POST /ia/api/v1/admin/auth/login`,体 `{"username","password"}` → Bearer 会话令牌(HS256,默认 4h;连续失败 5 次锁 15 分钟 → 423)。出处:`AdminAuthController.java` / `AdminSessionTokenService.java`。

**4.1 注册应用(登记 RSA 公钥)**:

```bash
# 生成宿主签名密钥对(私钥留在宿主,公钥登记)
openssl genrsa 2048 | openssl rsa -pubout

curl -s -X POST "http://localhost:18090/ia/api/v1/admin/apps" \
  -H "X-IA-Admin-Key: ${IA_ADMIN_KEY}" -H 'Content-Type: application/json' -d '{
    "appKey": "my-host-app",
    "name": "我的宿主应用",
    "signPublicKey": "-----BEGIN PUBLIC KEY-----\nMIIBIjANBgkq...\n-----END PUBLIC KEY-----",
    "webhookUrl": "https://host.example.com/ia/webhook",
    "webhookSecret": "whsec-9f2c1ab77d"
  }'
```

- `signPublicKey` 只接受 RSA 公钥 **PEM**;非法 PEM → 400「不是合法的 RSA 公钥 PEM」;`appKey` 重复 → 409。
- 响应 `data.signKeyFingerprint`(SHA-256 十六进制前 16 位)用于核对密钥。出处:`AdminAppController.java` / `AdminAppService.java`。
- webhook 也可后续经 `PUT /ia/api/v1/admin/webhooks/config` 配置(见 §6.3)。

**4.2 注册工具(宿主桥不主动推送,需在管理面登记)**:

starter 的职责边界:启动时扫描 `@IaTool` 注册进**宿主进程内**的 MCP server;InnerAgent 通过对 `endpoint_url` 周期性 `tools/list` 指纹轮询感知清单。因此**注册表条目由宿主方经管理面 API 写入**:

```bash
curl -s -X POST "http://localhost:18090/ia/api/v1/admin/tools" \
  -H "X-IA-Admin-Key: ${IA_ADMIN_KEY}" -H 'Content-Type: application/json' -d '{
  "serverKey": "my-host-app",
  "toolName": "get_customer",
  "description": "按客户 ID 查询客户姓名、等级与负责人",
  "riskLevel": "low",
  "source": "host_app",
  "endpointUrl": "http://localhost:18091/ia-mcp",
  "parametersSchema": "{\"type\":\"object\",\"properties\":{\"customer_id\":{\"type\":\"string\",\"description\":\"客户唯一 ID,形如 CUST-1001\"}},\"required\":[\"customer_id\"]}"
}'
```

要点(出处:`AdminToolController.java` / `ToolRegistryService.java`):

- `endpointUrl` = 宿主桥地址(默认 `http://<宿主>:<端口>/ia-mcp`),**必须与步骤 ③ 的 `act.audiences` 一致**;
- `serverKey` 仅允许字母/数字/连字符(禁下划线);`source` 取 `host_app` 或 `third_party`——只有 `host_app` 的注解被采信为策略软输入(V15);
- 模型可见名为确定性 FQN `mcp__<serverKey>__<toolName>`(如 `mcp__my-host-app__get_customer`);
- 同 FQN 重复注册 → 409(schema 变更走「刷新分诊」`POST /ia/api/v1/admin/tools/{id}/schema`,见《工具设计规范》§3)。

**4.3 授权(写工具免确认的通道)**:日常由**用户在确认卡**里产生(「本次/本会话/总是允许/拒绝」);管理员也可经 `POST /ia/api/v1/admin/grants` 预授:`{"userId":10086,"toolName":"mcp__my-host-app__update_customer_level","scope":"permanent"}`(`scope` ∈ `permanent|conversation`;`conversation` 必须带 `conversationId`)。出处:`AdminGrantController.java` / `ToolGrantService.java`。

**本步常见错误**:① 公钥贴成私钥/证书 → 400;② `endpointUrl` 与 `act.audiences` 不一致 → 工具体检能通但调用 401;③ `riskLevel` 给了 `READ/WRITE`(starter 词表)——管理面词表是 `low/medium/high`。

### 步骤 ⑤ 前端接入(SDK + Web Component)

前置:构建 SDK 产物 `cd sdk-js && pnpm install && pnpm build`(产出 `sdk-js/packages/components/dist/inneragent-chat.js`)。

```html
<inneragent-chat id="chat" view="chat"></inneragent-chat>
<style> inneragent-chat { display: block; height: 560px; } </style>
<script type="module">
  const sdk = await import('/js/inneragent-chat.js')

  sdk.init({
    appKey: 'my-host-app',            // 与管理面注册的 appKey 一致
    baseURL: '/ia/api/v1',            // 默认值;跨域部署时配绝对地址
    agentType: 'my_agent',            // 对话使用的 Agent 类型;缺省 'ai_media'(融光遗留)
    tokenGetter: async () => {        // 见下方实现说明
      const res = await fetch('/host/api/embed-token', { credentials: 'include' })
      if (!res.ok) return null        // 拿不到 → SDK 不重试,按 401 抛错
      return res.text()
    },
    // theme: { '--ia-primary': '#0ea5e9' },   // 可选:主题令牌
  })
  sdk.registerInnerAgentChat()        // 注册 <inneragent-chat>(幂等)
</script>
```

`init` 契约(出处:`sdk-js/packages/core/src/config.ts`):`TokenGetter = () => Promise<string | null>`;`baseURL` 默认 `/ia/api/v1`;`agentType` 默认 `'ai_media'`,随 `POST /runs` 请求体发送;`mode: 'iframe'` 为占位(会抛 `IframeModeNotImplementedError`)。

**tokenGetter 实现三要点**:

1. **懒加载**:SDK 在**每次 HTTP 请求与每次 SSE 连接前**调用它(出处:`sdk-js/packages/core/src/client.ts` 的 `resolveToken`、`sseAuth.ts`),不是初始化时取一次存死——回调内部应做缓存 + 过期前重签,避免每请求打宿主接口;
2. **401 重取**:收到 401 时 SDK 会**再次调用 tokenGetter 并用新 token 重试恰好一次**;并发 401 经单飞(`refreshTokenSingleFlight`)合并为一次重取(出处:`client.ts`)。因此宿主回调应支持「被反复调用」,在 token 过期后重新签发;
3. **null 语义**:返回 `null` 表示宿主明确给不出 token → SDK 不重试,按 401 抛错(`ApiError.isAuthError()` 为 true)。不要用抛异常表达「无 token」,返回 null。

宿主后端签发端点示例(nimbus-jose-jwt,与 starter 同源依赖;骨架级):

```java
@RestController
class EmbedTokenController {
    private final RSAPrivateKey privateKey; // 与管理面登记 signPublicKey 配对,私钥不出宿主

    @GetMapping("/host/api/embed-token")
    public String token() throws JOSEException {
        long now = System.currentTimeMillis() / 1000;
        JWTClaimsSet claims = new JWTClaimsSet.Builder()
                .issuer("my-host-app")                        // iss = appKey
                .subject("10086")                             // sub = 宿主用户 ID(数字串)
                .claim("tenantId", 1L)                        // 可选
                .issueTime(new Date(now * 1000))
                .expirationTime(new Date((now + 12 * 3600) * 1000)) // 建议有效期 12h
                .build();
        SignedJWT jwt = new SignedJWT(new JWSHeader.Builder(JWSAlgorithm.RS256).build(), claims);
        jwt.sign(new RSASSASigner(privateKey));
        return jwt.serialize();
    }
}
```

本地联调捷径:server 以 `local` profile 启动且 `inneragent.security.allow-anonymous-demo: true` 时,可用 `X-IA-Demo-User` 头或 `tokenGetter: async () => null` 匿名演示(出处:`inneragent-server/src/main/resources/application.yml` 与 `examples/demo-host/main.js`)。**生产严禁开启。**

## 3. 对话与运行(SDK 背后发生了什么)

| 动作 | API(出处:`AiPipelineController.java`) |
| --- | --- |
| 发起运行(SSE 流) | `POST /ia/api/v1/runs`(请求体含 `agentType`;响应 `text/event-stream`,事件 id 形如 `runId:seq`) |
| 断线续传 | `GET /ia/api/v1/runs/{runId}/events` + `Last-Event-ID` 请求头 |
| 工具确认 | `POST /ia/api/v1/runs/{runId}/confirm`,体 `{"replyId","decisions":[{"toolCallId","approved"}]}` |
| 取消 | `POST /ia/api/v1/runs/{runId}/cancel` |
| 运行状态 | `GET /ia/api/v1/runs/{runId}`(非终态 `RUNNING/WAITING_CONFIRMATION/WAITING_EXTERNAL/CANCEL_REQUESTED`;终态 `COMPLETED/FAILED/CANCELLED`) |

工具调用的完整闭环:模型决定调用 `mcp__my-host-app__update_customer_level` → 命中确认策略(WRITE 未授权)→ SSE 推确认事件(`USER_CONFIRMATION_REQUIRED`)→ 用户批准 → InnerAgent 经 MCP 客户端调宿主 `/ia-mcp`,附 `X-IA-Act`(60s)→ 宿主 Filter 验签 → 工具方法执行 → 结果回灌模型续跑 → 全程落审计(`ia_audit_log`)。

## 4. 令牌生命周期

### 4.1 embed token(前端 ↔ InnerAgent)

- **签发**:宿主后端 RS256 签名。必需 claims:`iss`(= appKey,服务端据此定位 `ia_app` 行)、`sub`(终端用户 ID,数字串)、`exp`。可选:`tenantId`。**无 `aud` claim**。算法强校验 RS256。出处:`inneragent-server/src/main/java/com/inneragent/server/auth/EmbedTokenVerifier.java`。
- **有效期**:由宿主在 `exp` 里自定,服务端只要求「存在且未过期」,注释建议 12h。建议配合 SDK 401 懒换(§2 步骤 ⑤)实现无缝续签。
- **公钥轮换与 72h 双钥宽限**:管理面 `PUT /ia/api/v1/admin/apps/{id}` 提交**不同的** `signPublicKey` 即触发轮换:旧公钥移入 `ia_app.previous_sign_public_key`,记录 `sign_key_rotated_at`。宽限期内(配置 `inneragent.auth.embed-key-grace`,默认 **72h**,支持 `30m/7d` 等 Duration 格式;配 0 或负值关闭)旧钥签发的存量 token 仍验签通过——宿主在窗口内完成换签,存量用户不被立即全量下线。出处:`DbAppSigningKeyProvider.java`、`application.yml` `inneragent.auth` 段、迁移 `V9__app_sign_key_rotation_grace.sql`。

### 4.2 act token(InnerAgent ↔ 宿主桥内环)

- **签发**:InnerAgent 在**每次 MCP `tools/call`(含懒建客户端的 initialize)前现签**,`TTL_SECONDS = 60`。claims:`iss=inneragent`、`aud=[endpoint_url]`、`sub=<userId>`、`act.sub=inneragent-run:{runId}`(RFC 8693)、自定义 `appKey/tenantId/toolName`、`exp/iat`;JWS 头带 `kid`(公钥 SHA-256 Base64URL 前 16 位)。出处:`inneragent-server/src/main/java/com/inneragent/server/auth/act/ActTokenIssuer.java`、`ActTokenKeyManager.java`。
- **JWKS**:`GET /.well-known/jwks.json`(server 根路径,无 `/ia` 前缀;出处:`JwksController.java`)。act 签名密钥经环境变量 `IA_ACT_KEY_PEM`(PKCS#8 PEM)或 `IA_ACT_KEY_PATH` 注入;两者都缺省则**临时生成**(重启即换、多实例不一致——生产必须注入)。
- **宿主侧消费**:starter 拉取 JWKS(默认 5min 周期刷新 + 未知 kid 强刷节流 5s + 消失密钥本地保留 72h),验签顺序:RS256 → kid 必填 → 签名 → `exp/nbf`(±30s 容忍)→ `iss` → `aud` 精确匹配 → `sub` 必填;任一失败统一 401 fail-closed。通过后 claims 写入工具上下文,`@IaTool` 方法可注入 `IaActClaims`(字段 `userId/actSub/runId/appKey/tenantId/toolName`)。出处:`IaActTokenVerifier.java`、`IaActJwksCache.java`、`IaActClaims.java`。
- **内环边界**:`X-IA-Act` 只出现在 InnerAgent → 宿主 `/ia-mcp` 的调用里;它不是给浏览器或三方系统的令牌。三方 MCP 接入走规范 OAuth 2.1 或用户配置静态头。

### 4.3 一页速记

| 事件 | 发生什么 | 你要做什么 |
| --- | --- | --- |
| 前端首次接入 | SDK 调 tokenGetter 拿 embed token | 宿主实现签发接口(RS256,私钥自持) |
| embed token 过期 | 请求 401 → SDK 重调 tokenGetter 重试一次 | 回调内重签即可,无需 SDK 侧配置 |
| 宿主换签名密钥 | 管理面 PUT 新公钥;旧钥 72h 宽限 | 在 72h 内把新私钥发布到签发服务 |
| InnerAgent 调工具 | 每 call 现签 60s act token | 宿主只需配对 `act.audiences` 与 `endpoint_url` |
| InnerAgent 换 act 密钥 | JWKS kid 变化 → 宿主强刷 + 72h 双钥 | 无需操作(starter 自动处理) |

## 5. 约束范围 resolve_scope(宿主契约)

InnerAgent 的核心机制之一是**约束范围反查**:Agent 在不确定可操作对象时调用标准工具 `resolve_scope` 向宿主求证(PRD §6.1.4)。**宿主在自己的 MCP 工具集中实现同名工具**即视为「已实现」,无需在管理面注册该条目。

**工具契约**(出处:`inneragent-server/src/main/java/com/inneragent/platform/toolhub/ResolveScopeRequest.java`、`ResolveScopeOutcome.java`、常量 `McpToolCatalog.RESOLVE_SCOPE_TOOL`):

```text
工具名:  resolve_scope
入参:    { "pageId": string, "objectId": string, "objectType": string,
           "custom": { k: v, ... } }            // 由 SDK 上报的前端上下文组装
出参:    { "visibleDomains": ["订单"],           // 当前上下文可见对象域
           "writableFields":  ["order.remark"],  // 可写字段
           "forbidden":      ["删除订单"],       // 禁止操作清单
           "hints":          ["用户仅可见华东区"] } // 附加提示
```

- 四个数组均为字符串列表,字段「宽进」:缺字段/类型不符一律按空列表容忍——**宿主是协议的最终裁决方**。
- 边界:InnerAgent 只传递与呈现 scope,越权拦截由宿主工具侧执行(ADR-3):工具方法内仍须按 `IaActClaims.userId` 做行级校验。

**未实现时的降级语义**(出处:`ResolveScopeService.java`):注册表查无 `resolve_scope` 工具(`tool_absent`)或 MCP 调用通道不可用(`invoker_unavailable`)→ 本次运行标记 `scopeDegraded`,行为为:

- 无约束范围上下文(run 的 scope 节点记 `{"resolved":false,"degraded":true}`,出处:`AgentExecutionFactory.scopeNode`);
- **写操作一律 ASK 确认,且任何用户授权不得绕过**——`AgentToolPermissionPolicy` 的 DEFAULT 分支带 `!scopeDegraded` 守卫(出处:`inneragent-server/src/main/java/com/inneragent/agent/permission/AgentToolPermissionPolicy.java`)。也就是说:不实现 `resolve_scope` 不会不安全,但用户体验降级(每次写都要点确认)。接入体检会提示推荐实现。

**REST 转发(可选)**:宿主实现 `resolve_scope` 工具时,可把反查转发回 InnerAgent 的薄封装 `POST /ia/api/v1/tools/resolve-scope`(响应为四数组裸对象,无 CommonResult 信封)。出处:`inneragent-starter/.../client/InnerAgentBridgeClient.java`(`RESOLVE_SCOPE_PATH`)与 `inneragent-server/.../controller/ToolScopeController.java`。

### 6.2 紧急停用

```bash
curl -s -X POST "http://localhost:18090/ia/api/v1/admin/circuit-breaker/emergency-stop?appId=1" \
  -H "X-IA-Admin-Key: ${IA_ADMIN_KEY}" -H 'Content-Type: application/json' \
  -d '{"reason": "失控循环,成本异常"}'

# 逐个终止进行中的 run(没有批量取消)
curl -s -X POST "http://localhost:18090/ia/api/v1/admin/circuit-breaker/terminate-run?appId=1" \
  -H "X-IA-Admin-Key: ${IA_ADMIN_KEY}" -H 'Content-Type: application/json' \
  -d '{"runId": "<runId>", "reason": "紧急停用清场"}'

curl -s -X POST "http://localhost:18090/ia/api/v1/admin/circuit-breaker/resume?appId=1" -H "X-IA-Admin-Key: ${IA_ADMIN_KEY}"
curl -s "http://localhost:18090/ia/api/v1/admin/circuit-breaker?appId=1" -H "X-IA-Admin-Key: ${IA_ADMIN_KEY}"  # 状态+最近20条事件
```

语义边界(出处:`CircuitBreakerAdminService.java`、`V14` DDL 注释、`AgentScopePipelineRunService.java` 的 `assertRunStartAllowed` 调用点):

- 总开关只拒**新 run**:停用后发起 run/续跑 → 403「应用已紧急停用:…,新运行已被拒绝,请等待管理员恢复后再试」;
- **进行中的 run 不会被批量取消**,需管理员逐个 `terminate-run`(复用取消通道,CANCELLED 终态,审计 `run-terminated / forced-policy`);
- 终止/停用/恢复全部落 `ia_circuit_event` 仅追加流水(`emergency-stop / resume / run-terminated`;`limit-triggered` 为保留值暂不发)。

### 6.3 Webhook 订阅(运行终态回调)

**配置**(出处:`AdminWebhookConfigController.java`;也可在注册应用时给 `webhookUrl/webhookSecret`):

```bash
curl -s -X PUT "http://localhost:18090/ia/api/v1/admin/webhooks/config?appId=1" \
  -H "X-IA-Admin-Key: ${IA_ADMIN_KEY}" -H 'Content-Type: application/json' \
  -d '{"url": "https://host.example.com/ia/webhook", "secret": "whsec-9f2c1ab77d",
       "enabled": true, "events": ["run.finished","run.failed","run.cancelled"]}'
# 连通性测试(真实签名单发,返回 {ok, signatureValid, httpStatus, error})
curl -s -X POST "http://localhost:18090/ia/api/v1/admin/webhooks/config/test?appId=1" -H "X-IA-Admin-Key: ${IA_ADMIN_KEY}"
```

可订阅事件:`run.finished / run.failed / run.cancelled`(`run.resource-limit` 为 web 契约保留值,当前不产生投递)。非法事件 → 400。

**验签**(出处:`WebhookSigner.java`、`WebhookDeliveryService.headers()`):请求头四个——`X-IA-Signature`、`X-IA-Timestamp`(epoch 毫秒)、`X-IA-Nonce`、`X-IA-Delivery`(投递记录 ID,宿主幂等去重键)。签名为 `HMAC-SHA256(secret, timestamp + "." + nonce + "." + body)` 小写十六进制;宿主按同串重算比对即可。载荷:`{event, appId, runId, status, finishedAt, errorCode?, errorMessage?}`。

**重试与终态**(出处:`WebhookDeliveryProperties.java`、`WebhookDelivery.java`):非 2xx 按 `1m → 5m → 30m → 2h → 12h` 退避,最多 **5 次**(含首投),单次 HTTP 超时 10s;状态机 `PENDING → SUCCESS | FAILED → EXHAUSTED`。EXHAUSTED 只能人工重投:

```bash
curl -s -X POST "http://localhost:18090/ia/api/v1/admin/webhook-deliveries/{id}/redeliver" -H "X-IA-Admin-Key: ${IA_ADMIN_KEY}"
curl -s "http://localhost:18090/ia/api/v1/admin/webhook-deliveries?appId=1&status=FAILED" -H "X-IA-Admin-Key: ${IA_ADMIN_KEY}"
```

重投把记录复位 `PENDING` 且尝试计数清零;已 `PENDING` 的记录重投 → 409。

### 6.5 错误语义表

统一响应信封 `{"code": <http同码>, "msg": "...", "data": ...}`(出处:`CommonResult.java`、`GlobalExceptionHandler.java`——其内嵌 `ErrorSemantics` 枚举即本表来源)。SSE/长连接中的客户端断连(`Broken pipe` 等)按正常断流静默处理,不回错误体。

| HTTP | 触发 | 用户该做什么 |
| --- | --- | --- |
| **400** | 请求体不合法 / 缺必填参数 / 参数类型错 / 业务校验失败(含非法 PEM、非法事件、limits 超值域);注意:**base64 附件 >10MB、url 附件 >20MB 也是 400**(业务层校验) | 按报文修正请求体或参数后重试 |
| **401** | embed token 缺失/过期/验签失败;act token 错配(宿主桥返回);管理面凭证错误 | 前端:SDK 自动懒换重取一次,仍失败检查 tokenGetter;宿主桥:对齐 `act.audiences` 与 `endpoint_url` |
| **403** | 无权限;**应用已紧急停用(新 run 被拒)**;管理面 `IA_ADMIN_KEY` 未配置或错误 | 等待管理员恢复停用;接入方检查管理面密钥注入 |
| **404** | 资源不存在(含他人附件——不泄露存在性) | 核对 ID 与归属 |
| **405** | HTTP 方法不支持(如对无状态 `/ia-mcp` 发 GET) | 核对接口方法 |
| **409** | 冲突:appKey/tool FQN 重名、重复注册、重复授权并发、约束冲突、对终态 run 再终止 | 刷新后重试;重复提交无需重试 |
| **413** | multipart 上传超 `spring.servlet.multipart.max-file-size`(默认 20MB) | 压缩或拆分文件后重传 |
| **500** | 未归类系统错误 | 携 `X-Trace-Id` 联系服务方 |
| **502** | 上游不可达(模型连通性测试、宿主桥、webhook 测试的连接失败/超时) | 检查上游地址/网络后重试 |
