# 快速开始 · 02 宿主应用接入(以 ACME demo 为骨架)

> 目标:以参考实现 `examples/acme-demo/` 为骨架,走通"注册应用 → 写工具 → 签发身份 →
> 前端挂组件 → 工具调用闭环"的最小接入。约 20 分钟。
>
> 前置:[01-五分钟跑起来](01-五分钟跑起来.md) 的 server 已在 `:18090` 运行。

## 0. 你将扮演的角色

```
平台方(你,运营 InnerAgent)          接入方(demo 里的 "ACME",即你未来自己的应用)
  管理面登记 appKey + 公钥              宿主后端:持私钥、@IaTool 工具、Webhook 验签
  管理面登记工具(serverKey)             宿主前端:登录态 + <inneragent-chat>
```

## 1. 生成宿主签名密钥对(一次性)

```bash
openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:2048 -out host.key
openssl pkey -in host.key -pubout -out host.pub
```

**私钥只留在宿主后端**(注入 `IA_SIGN_PRIVATE_KEY`),公钥登记给平台。

## 2. 管理面开通(一次性,两条 curl)

```bash
# ① 注册应用(公钥 + webhook)
curl -s -X POST "http://localhost:18090/ia/api/v1/admin/apps" \
  -H "X-IA-Admin-Key: ${IA_ADMIN_KEY}" -H 'Content-Type: application/json' -d '{
    "appKey": "acme-demo",
    "name": "ACME 演示应用",
    "signPublicKey": "-----BEGIN PUBLIC KEY-----\n…(host.pub 内容)…\n-----END PUBLIC KEY-----",
    "webhookUrl": "http://localhost:9300/ia/webhook",
    "webhookSecret": "whsec-acme-demo-seed"
  }'

# ② 登记宿主工具(endpointUrl 指向宿主桥;与后端 act.audiences 对齐)
curl -s -X POST "http://localhost:18090/ia/api/v1/admin/tools" \
  -H "X-IA-Admin-Key: ${IA_ADMIN_KEY}" -H 'Content-Type: application/json' -d '{
  "serverKey": "acme-demo", "toolName": "create_ticket",
  "description": "在 ACME 宿主系统中创建一张工单",
  "riskLevel": "low", "source": "host_app",
  "endpointUrl": "http://localhost:9300/ia-mcp",
  "parametersSchema": "{\"type\":\"object\",\"properties\":{\"title\":{\"type\":\"string\"},\"description\":{\"type\":\"string\"},\"priority\":{\"type\":\"string\"}}}"
}'
```

## 3. 跑宿主后端(Java 21,`examples/acme-demo/backend`)

```bash
cd examples/acme-demo
openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:2048 -out seeds/.local/host.key   # 若未做 §1

cd backend
IA_SERVER_BASE=http://localhost:18090 \
IA_APP_KEY=acme-demo \
IA_SIGN_PRIVATE_KEY="$(cat ../seeds/.local/host.key)" \
IA_WEBHOOK_SECRET=whsec-acme-demo-seed \
IA_ADMIN_KEY=test-key \
mvn spring-boot:run        # :9300;启动日志应出现「4 个宿主工具 @ /ia-mcp」注册行
```

demo 里已写好四个工具:`AcmeTicketTools` 三个(`create_ticket`(WRITE)、
`list_tickets`/`resolve_scope`(READ))+ `AcmeSalesTools` 一个(`query_sales`(READ))
—— 你的应用里对应的就是普通业务方法加注解:

```java
@IaTool(name = "create_ticket", description = "创建工单", riskLevel = ToolRiskLevel.WRITE)
public Ticket create(@IaToolParam("title") String title, ...) { ... }
```

## 4. 跑宿主前端(Node 20+,`examples/acme-demo/frontend`)

```bash
cd ../frontend && pnpm install && pnpm dev   # http://localhost:9203
```

打开 `http://localhost:9203`,演示轻登录后进入对话页:后端 `/api` 签发 embed token,
前端以 `<inneragent-chat>`(WC 模式)直挂,`/ia` 代理到 18090。

## 5. 验收:工具调用完整闭环

在对话框输入(与 demo 模型脚本对齐的触发语):

```
帮我建一张工单:标题=打印机坏了,描述=3楼打印机卡纸,优先级=high
```

预期时序:

1. 模型发起 `create_ticket` 工具调用 → 平台推 **确认卡**(`USER_CONFIRM_REQUIRED`);
2. 你点确认 → 平台以 act token(`X-IA-Act`,60s)调宿主 `/ia-mcp` → 真实建单;
3. 对话流收到 `TOOL_FINISHED`(工具结果回传)+ 建单结果续写,最终 `DONE`;
4. demo 前端工具面板(TechnicalBoard)能看到 channel=agent 的工单卡片;
5. demo 后端日志有一条 Webhook 事件(验签通过)。

## 6. 从 demo 到你的应用(映射表)

| demo 里的东西 | 你的应用里对应 |
| --- | --- |
| `acme-demo` appKey + host.key | 你的 appKey + 你生成的密钥对 |
| `AcmeTicketTools` 三个 @IaTool | 你的业务方法(命名/分级见《工具设计规范》) |
| `EmbedTokenController` 签发 | 你的登录态 → embed token 的网关接口 |
| `EmbedChat.vue`(WC 模式) | 你的页面挂 `<inneragent-chat>` |
| `IaWebhookVerifier` | 你的 Webhook 订阅端点(原始字节验签、快回 2xx) |

## 7. 常见问题速查

| 症状 | 原因/处置 |
| --- | --- |
| 前端 401/CORS 报错 | server `IA_CORS_ALLOWED_ORIGINS` 未含前端来源;embed token 过期 |
| 工具从未被调用 | 工具未注册/endpointUrl 与 act.audiences 不一致;模型不支持 tool-calling |
| 一直 WAITING_CONFIRMATION | 确认卡未被处理(超时默认 24h);ALWAYS_ASK 模式属预期 |
| Webhook 401/验签失败 | secret 不一致;务必用**原始字节**验签、常量时间比较 |
