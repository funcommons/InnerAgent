## 1. 命名与 FQN

### 1.1 模型可见名是确定性 FQN

```text
mcp__<serverKey>__<toolName>
例:mcp__demo-spring-host__get_host_time
```

出处:`inneragent-server/src/main/java/com/inneragent/platform/toolhub/ToolRegistryService.java`(`FQN_PREFIX = "mcp__"`、`fqnOf`/`toolNameOf`)。

**规则:**

| 项 | 约束 | 违反后果 |
| --- | --- | --- |
| `serverKey` | 仅字母/数字/连字符 `[A-Za-z0-9-]{1,64}`,**避用下划线**(V25——下划线是 FQN 分隔符) | 400「serverKey 仅允许字母/数字/连字符」 |
| `toolName` | ≤ 128 字符 | 400 |
| 完整 FQN | ≤ 200 字符 | 400 |

命名纪律(V28 ②):`toolName` 用 `资源_动作`(如 `order_cancel`);`serverKey` 用宿主标识(如 `acme-crm`);参数名带归属:`customer_id`,不要裸写 `id`。`toolName` 避免再含 `__`,避免与 FQN 解析歧义。

### 1.2 命名冲突保护(注册时强制)

出处:`ToolRegistryService.register()`,三类冲突一律 **409**:

1. **与内置工具重名**:`toolExecutorRegistry.findExecutor(toolName) != null` → 拒绝;
2. **应用内工具名唯一**:另一 `serverKey` 已注册同名 `toolName` → 拒绝(工具名应用内唯一,多应用以 app 隔离);
3. **同 FQN 活跃行重复注册**:同 FQN 再次 `POST` → 409。schema 变更**不允许**用重注册表达,必须走「刷新分诊」(§3)。逻辑删行的同名重注册会**复活**原条目(DEF-03 修复后语义,审计留 `tool_revived`)。

## 2. schema 要求与指纹机制

### 2.1 parametersSchema

- 注册/刷新接口接受 JSON Schema 字符串;**非合法 JSON → 400**。空/空白 schema 合法(「无 schema 工具」,落库为 NULL),但**强烈不建议**——模型只能盲猜参数(反模式 #1,见 §7)。
- 用 starter 的 `@IaTool` 时,schema 由方法签名**自动生成**(出处:`inneragent-starter/src/main/java/com/inneragent/starter/IaToolSchemas.java`),参数顺序即 properties 顺序(保证指纹稳定)。类型映射:

| Java 类型 | JSON Schema type |
| --- | --- |
| `String`/`char` | `string` |
| 枚举 | `string` + `enum: [常量名]` |
| `boolean`/`Boolean` | `boolean` |
| `byte/short/int/long` 及包装 | `integer` |
| `float/double/BigDecimal` | `number` |
| 数组 / `Collection` | `array`(+`items`) |
| 其余(`Map`/POJO/record) | `object`(运行期以 JSON Map 进入方法,**无 POJO 反序列化绑定**) |

- 可注入参数:`IaActClaims` 类型参数被识别为身份注入,不进 schema、不要求调用方传参。

**大参数注意(现状)**:本工程没有 `maxRequestSize` 旋钮——所钉 mcp 0.17.0 客户端传输不设请求体上限、无 413 路径(出处:`inneragent-server/src/main/java/com/inneragent/agent/mcp/McpInvokerProperties.java` 类注释,spike 风险 R6)。真实存在的上游限制是**运行入口 ingress**:`4096 事件 / 8MB`(`application.yml` `fusion.agentscope.v2.ingress`)与模型上下文窗口。因此工具参数与返回体都应自持分寸(反模式 #6):分页、`limit`、字段裁剪由工具自己负责。

### 2.2 指纹机制(sha256 规范化)

出处:`inneragent-server/src/main/java/com/inneragent/platform/toolhub/ToolSchemaFingerprint.java`:

1. `parametersSchema` 解析为树后**递归按键名排序**(TreeMap,数组保序)序列化为规范 JSON——**属性声明顺序不影响指纹**;
2. 对规范 JSON 取 SHA-256,作为 `schemaSha256` 落 `ia_tool_registry`(分诊基准),并快照进每条授权 `ia_tool_grant.schemaSha256`。

注册表级指纹(活刷新分诊基准)与运行级内核快照 pinning 是**双层策略、刻意解耦**(ADR-5):运行中工具集按快照不漂移;注册表按分诊演进。

### 2.3 活刷新分诊三态(V14 裁定)

管理面触发:`POST /ia/api/v1/admin/tools/{id}/schema`,体 `{"parametersSchema": "...", "annotationsJson": "...", "toolVersion": "..."}`;响应 `TriageRespVO{verdict, reasons, revalidateRequired, effectiveSchemaSha256, pendingSchemaSha256}`(出处:`AdminToolController.java`、`SchemaTriageService.java`)。

| verdict | 判定依据 | 生效方式 | 历史留痕 outcome |
| --- | --- | --- | --- |
| `unchanged` | schema 未重发(空体)或指纹与基准一致 | 仅更新元数据/版本,**不动指纹与授权** | `silent_refresh` |
| `compatible` | 指纹有差但安全矩阵不变(如新增可选属性、纯嵌套变化 `nested_schema_changed`) | **立即生效**并审计 `schema_compatible`;授权不失效;`resumeSafe` 跟随新 `idempotentHint` | `applied` |
| `breaking` | 命中安全矩阵(下表) | **不生效**,暂存 `pendingSchema*`、`revalidateRequired=true`,**级联失效该工具全部用户授权**(reason=`schema_breaking`);待管理员 `POST .../schema/confirm` 应用或 `POST .../schema/reject` 丢弃 | `pending_review` / `rejected` |

**breaking 安全矩阵**(出处:`SchemaTriageService.triage`):

- `readOnlyHint_flipped`(**任意方向**的翻转,含 true→false 放宽);
- `destructiveHint` false→true(收紧;true→false 视为 compatible);
- `required_added:*`(新增必填参数);
- `type_changed:*`(参数类型变化)。

**空体刷新 = unchanged(DEF-02 语义)**:next schema 为空/空白一律视为「未重发 schema」,返回 `unchanged(reasons=["schema_not_resent"])`——不改指纹、不落 pending、不级联失效;空串指纹(e3b0c442…)**绝不入库覆写**。出处:`ToolRegistryService.refreshSchema` 的 `schemaResent` 守卫与 `SchemaTriageService.triage` 开头分支(R1 轮 DEF-02 缺陷修复定型,`test-report/2026-09-21-02/03-工具注册与分诊.md` L3-05b 回归)。给工具作者的含义:**不要靠「刷新」按钮发空体来做任何变更**;变更必须带完整新 schema。

## 3. 风险分级与确认档位

### 3.1 两套词表及其映射

| starter 声明(`@IaTool.riskLevel`,出处:`starter/ToolRiskLevel.java`) | 派生 MCP 注解 | 管理面词表(`ia_tool_registry.riskLevel`,出处:`toolhub/ToolRiskLevel.java`) |
| --- | --- | --- |
| `READ` | `readOnlyHint=true` | `low`(`defaultFromAnnotations`) |
| `WRITE`(缺省) | 两者皆 false | `medium` |
| `DESTRUCTIVE` | `destructiveHint=true` | `high` |

**强制高危**(管理员也压不下去,注册与更新两处都执行):工具名或描述命中 `FORCED_HIGH_KEYWORDS`——删除类(`delete/remove/drop/destroy/purge/删除`)、资金类(`payment/refund/billing/charge/withdraw/transfer_money/付款/退款/资金`)、凭据类(`password/passwd/credential/secret/api_key/apikey/密码/凭据`)→ 一律 `high`。出处:`toolhub/ToolRiskLevel.java`。

### 3.2 确认档位与授权

权限模式(出处:`inneragent-server/src/main/java/com/inneragent/agent/permission/ToolExecutionMode.java`、`AgentToolPermissionPolicy.java`):

| 模式 | 行为 |
| --- | --- |
| `DEFAULT`(默认) | 只读(`readOnlyEffective=true`)**自动执行**;写操作**需确认** |
| `ALWAYS_ASK` | **所有工具逐次确认(含只读)**且授权不可绕过——代码注释原话「ALWAYS_ASK 一律确认」,较 PRD V19「不对只读调用逐次询问」更严,以代码为准 |
| `ALWAYS_ALLOW` | 全部自动执行(仅低风险场景) |
| `FULL_ACCESS` | 平台管理员专用;宿主侧校验仍生效 |

用户授权(`ia_tool_grant`,出处:`ToolGrantService.java`):`scope ∈ permanent | conversation`(`conversation` 必带 `conversationId`,否则 400);授权快照 `riskAtGrant` 与 `schemaSha256`——**风险升级或 breaking schema 变更自动失效授权**(reason=`risk_upgrade`/`schema_breaking`),工具停用/注销级联失效。重复活跃授权 → 409(并发窗口由唯一索引兜底,DEF-04)。

DEFAULT 档位判定表(核心逻辑,出处:`AgentToolPermissionPolicy.contextFor`):

| 工具 | 状态 | 行为 |
| --- | --- | --- |
| 只读 | — | ALLOW(decisionSource=`mode-default`) |
| 写 | 有有效授权 | ALLOW(`user-grant`) |
| 写 | 无授权 | **ASK**(`mode-default`) |
| 写 | 无授权 + `scopeDegraded`(resolve_scope 降级) | **ASK,且授权不绕过** |
| 任意 | 管理员 `adminPolicy=force-ask` | ASK(`forced-policy`,不可被授权绕过) |

给工具作者的操作指引:

- 读工具如实标 `READ`——用户体验最好(免确认);**把写工具标成 READ 绕确认是严重反模式**(#5):删除/资金/凭据类有关键词兜底强制高危,其余会被审计(`decisionSource` 全程可查)与 breaking 分诊盯住,且违反平台规范,一经发现应立即整改并视为安全事故;
- 写工具默认 `WRITE` 即可,确认与「总是允许」通道由平台提供;`DESTRUCTIVE` 只用于删除/资金/凭据类,平台会强制 `high` 并在升级时自动作废存量授权;
- 确认卡展示工具名、参数摘要、风险等级与影响对象——你的 `description` 与参数 `description` 直接决定用户能不能判断该不该批(反模式 #4)。

### 3.3 scopeDegraded 语义

宿主未实现 `resolve_scope`(或调用通道不可用)时该次运行 `scopeDegraded=true`:**写操作一律 ASK,任何授权都不绕过**(出处:`AgentExecutionRuntimeContextRequests.java` 计算 + `AgentToolPermissionPolicy.DEFAULT` 分支 `!scopeDegraded` 守卫;run 的 scope 节点记 `{"resolved":false,"degraded":true}`,出处:`AgentExecutionFactory.scopeNode`)。即:降级不牺牲安全,只牺牲流畅度——工具作者无需为此做任何事,但接入方应知道这是「为什么我的写工具总是要确认」的第一排查项。

## 4. 注解(MCP hints)

### 4.1 注解缓存与 V15 可信采信

注册表持久化 MCP 注解(出处:`inneragent-server/src/main/java/com/inneragent/platform/toolhub/ToolAnnotations.java`):

```java
record ToolAnnotations(String rawJson, Boolean readOnlyHint, Boolean destructiveHint,
                       Boolean idempotentHint, Boolean openWorldHint)
```

**V15 裁定:注解是 hints,规范明示不可信——仅可信宿主(`source=host_app`)服务器的注解被采信为策略软输入;三方(`third_party`)工具一律按写处理。** 出处:`McpToolCatalogEntry.java` 的 `trusted` 门:`readOnlyEffective = trusted && readOnlyHint`。策略上直接消费的是 `readOnlyEffective`(DEFAULT 档 ALLOW/ASK 分叉);三方工具的 `readOnlyHint=true` 会被无视 → 恒 ASK。

starter 用户注意:`@IaTool` 注解本身**只有 `name/description/riskLevel` 三个属性**(出处:`starter/IaTool.java`),`readOnlyHint/destructiveHint` 由 `riskLevel` 派生(`READ→readOnlyHint=true`、`DESTRUCTIVE→destructiveHint=true`),并以 `_meta: {"ia.riskLevel": ...}` 随 `tools/list` 暴露(出处:`starter/IaToolDefinition.toMcpTool`)。宿主不需要、也无法在方法级手写其余 hint——需要更细的注解时在管理面登记/刷新 `annotationsJson`。

### 4.2 resumeSafe / concurrencySafe

| 字段 | 语义 | 缺省 |
| --- | --- | --- |
| `resumeSafe` | 该工具可被 `continue`(续跑/重执行)安全重放——即**幂等**。注册时取 MCP `idempotentHint`(V34);分诊 compatible 时跟随新值 | `idempotentHint` |
| `concurrencySafe` | 并发调用安全(无共享可变状态竞争) | 手工维护 |

实践口径:查询类天然 `resumeSafe=true`;「创建」类若以业务键幂等(同键 upsert)可标 true,否则 false;带副作用的支付/发消息类必须 false。`idempotentHint` 同时是**自动重试门槛**——标 true 的只读工具失败后平台才考虑自动重试(§4.7 资源上限 `toolRetryLimit`,仅对幂等只读工具)。

## 5. 工具体检(现状与自查)

**现状标注(基于 HEAD=`6ab251c`)**:PRD 规划的「工具体检 v1」静态检查与健康三态**尚未落地**:

- `ia_tool_registry.last_test_status`(「最近一次工具体检/连通性测试结果」)列已建但**当前无写入方**(出处:`V2__app_and_tool_registry.sql` 列注释;全库检索无写点);
- 不存在 `check-batch`/批量体检端点;`AdminToolController` 只有单工具粒度的刷新分诊与启停接口;
- 已实现的「体检面」是:①注册表条目的**活刷新分诊**(`POST /admin/tools/{id}/schema`,§2.3);②用户级 MCP 服务器的连通测试 `POST /ia/api/v1/me/mcp/{id}/test` → `last_test_status ∈ null | "success" | "failed"`(出处:`AgentMcpServerService.recordTest`)。

**宿主桥连通性体检失败的自查清单**(按命中概率排序):

1. `curl http://<宿主>:<端口>/ia-mcp` 发无状态 `tools/call`/`tools/list` 探活——401?→ 查 `act.audiences` 与 `endpointUrl` 是否一致(最高频,见《接入指南》§2 步骤③);
2. 宿主 `server-base` 未配或 JWKS 拉不到 → 宿主侧日志应有「JWKS 不可达,/ia-mcp 全量 401 fail-closed」WARN;
3. InnerAgent 侧 `inneragent.mcp.enabled=false` → 回退 `UnavailableMcpToolInvoker`,任何宿主工具调用直接报「MCP 工具调用尚未接管」(出处:`UnavailableMcpToolInvoker.java`);
4. 宿主进程未起 / `tool-packages` 写错包名 → `tools/list` 空;
5. act 密钥轮换后宿主 JWKS 缓存未刷 → 等 `forced-refresh-cooldown`(5s)或重启宿主;72h 内旧 kid 仍可用;
6. 注册表条目 `enabled=false` → 内核白名单不可见;停用会级联失效授权。

调用期失败语义:宿主返回 `isError=true` → 错误**回灌模型可续跑**;基础设施故障(401/403→`McpToolAuthException`、超时→`McpToolTimeoutException`、断连→`McpToolTransportException`)触发单飞重连编排(退避 200ms→5s,重试一次)后仍失败才上抛。出处:`McpClientToolInvoker.java`。

## 6. 完整示例:正例与反例对照

### 6.1 正例(读 + 写)

```java
@Component
public class OrderTools {

    private final OrderService orderService;   // 宿主业务服务(构造注入)

    public OrderTools(OrderService orderService) { this.orderService = orderService; }

    /** 读:任务型命名 + 精确参数 + 上下文化返回。 */
    @IaTool(name = "get_order",
            description = "查询订单:返回订单号、状态、金额、下单人与最近一次物流事件。"
                    + "仅返回调用者有权查看的订单。",           // 描述=新人入职文档(边界说清)
            riskLevel = ToolRiskLevel.READ)
    public Map<String, Object> getOrder(
            @IaToolParam(value = "order_no", description = "业务订单号,形如 SO-20260921-0001") String orderNo,
            IaActClaims claims) {
        return orderService.findView(orderNo, claims.userId())  // 行级权限在宿主侧终审(ADR-3)
                .map(v -> Map.of("status", "ok", "order", v))    // 返回人话名,不吐内部 uuid 单字段
                .orElseGet(() -> Map.of(
                        "status", "error",
                        "message", "订单 " + orderNo + " 不存在或无权查看;请确认订单号后重试"));
    }

    /** 写:WRITE 走确认;幂等设计使 resumeSafe 可标 true。 */
    @IaTool(name = "update_order_remark",
            description = "修改订单备注(全文覆盖)。修改后原备注不可恢复。",
            riskLevel = ToolRiskLevel.WRITE)
    public Map<String, Object> updateOrderRemark(
            @IaToolParam(value = "order_no", description = "业务订单号") String orderNo,
            @IaToolParam(value = "remark", description = "新备注内容,1-200 字") String remark,
            IaActClaims claims) {
        orderService.updateRemark(orderNo, remark, claims.userId()); // 同键覆盖:天然幂等
        return Map.of("status", "ok", "orderNo", orderNo,
                      "updatedBy", claims.userId(), "runId", claims.runId());
    }
}
```

正例要点:命名 `服务-资源-动作`;参数 `order_no` 不裸写 `id`;描述交代返回什么、边界是什么;错误信息可操作(下一步做什么);写操作以业务键幂等;行级权限在宿主侧按 act 身份终审。

## 7. 设计反模式清单(实测经验提炼)

以下反模式来自 R1~R4 四轮 E2E 实测(`test-report/2026-09-21-0{1..4}`)、spike 风险记录(`spikes/mcp-bridge-spike/FINDINGS.md`)与 V28 五条对标,每条给出正确做法:

| # | 反模式 | 后果(实测/机制依据) | 正确做法 |
| --- | --- | --- | --- |
| 1 | **空/无 schema 注册**:不带 `parametersSchema`,或参数描述缺失 | 模型盲猜参数,首次调用必失败;空体「刷新」曾污染指纹链路(R1 DEF-02,已由 unchanged 语义封堵,但空 schema 工具依旧不可用) | 每个参数给 `@IaToolParam(description=...)` 与准确类型;可选参数显式 `required=false` |
| 2 | **1:1 端点包装**:把 REST CRUD 三件套原样包装成 `create_order/update_order/delete_order/get_order` | 模型要多轮试错拼调用序列;工具体检按 V28 将标记 1:1 包装 | 任务型合并:`schedule_event` 而非 `create_event+patch_event+delete_event`(V28 ①) |
| 3 | **命名不纪律**:`serverKey` 带下划线、`toolName` 无动作语义、参数裸写 `id/user` | `serverKey` 含下划线直接 400;裸参数让模型填错对象 | `[A-Za-z0-9-]` 的 serverKey;`资源_动作` 工具名;`customer_id` 式参数名(V28 ②) |
| 4 | **描述空洞或写给开发者**:「调用该接口更新数据」;不写边界、副作用、单位 | 用户在确认卡上看不出影响对象 → 不敢批/误批;模型选错工具 | 描述=新人入职文档:做什么、返回什么、有什么限制与副作用(V28 ③) |
| 5 | **高危标 READ 绕确认**:删除/资金操作声明 `riskLevel=READ`,或命名刻意避开 `delete/payment` 关键词 | 关键词兜底可能被命名规避,但审计全留痕、breaking 分诊盯 `readOnlyHint` 翻转;属安全事故级违规 | 如实分级;破坏性必须 `DESTRUCTIVE`(平台强制 `high`、授权升级自动作废) |
| 6 | **返回体过大**:整表返回、返回原始 DB 行、无分页 | 撑爆上下文(模型窗口)与 ingress 8MB 上限;平台无 maxRequestSize 兜底(R6) | `limit/offset` 参数 + 字段裁剪;返回人话名而非 uuid 全集(V28 ④) |
| 7 | **长阻塞无超时**:工具内同步等待外部系统(人工审核、慢接口)直至天级 | 平台侧 `call-timeout 30s` 必然断(`application.yml` `inneragent.mcp.call-timeout`);run 卡死占并发 | 快速返回任务 id + 配套查询工具;或异步回调 + `resumeSafe` 幂等重放 |
| 8 | **meta/返回内嵌业务态**:把会话状态、页码游标藏在工具返回要求模型背回;工具间靠隐式状态耦合 | 状态跨 run 不可靠(运行按工具快照);模型记不住大 JSON | 无状态工具:状态归宿主库,工具间传业务 id;游标做成显式参数 |
| 9 | **幂等标注失真**:非幂等写漏标 `idempotentHint=false`(或管理面 `resumeSafe` 误开);纯读却标非幂等 | 前者:续跑重放会重复扣款/重复建单;后者:失去自动重试与免确认通道 | 按「同参重放是否产生二次副作用」如实标注(§4.2 口径) |
| 10 | **错误返回栈或含糊**:把异常堆栈/「操作失败」塞给模型 | 模型无法自纠,反复重试同一错法;泄露内部实现 | `isError` 语义 + 可操作 message:错在哪、该改什么(正例 §6.1;V28 ④) |
| 11 | **与内置/三方撞名**:工具名叫 `get_current_time` 等内置名,或两个 serverKey 注册同名工具 | 注册 409 拒绝(冲突保护),接入卡在登记步骤 | 注册前用 `GET /ia/api/v1/admin/tools?serverKey=` 查重;工具名带服务前缀语义 |
| 12 | **eval 缺位**(V28 ⑤):上线后不看模型实际调用表现 | 冗余调用=分页/描述问题;非法参数=schema 问题——这些信号不回收,工具永远停留在 v1 | 按宿主建任务集跑对照;用审计(`toolFqn`+`decision`)统计误用率迭代描述与 schema |

## 8. 注册与治理 API 速查

管理面基路径 `/ia/api/v1/admin`(鉴权见《接入指南》§2 步骤④)。出处:`AdminToolController.java`、`AdminGrantController.java`。

| 操作 | API |
| --- | --- |
| 注册工具 | `POST /admin/tools`(serverKey/toolName/source 必填;冲突 409) |
| 刷新分诊 | `POST /admin/tools/{id}/schema` → `unchanged/compatible/breaking` |
| breaking 处置 | `POST /admin/tools/{id}/schema/confirm` / `POST /admin/tools/{id}/schema/reject` |
| schema 历史 | `GET /admin/tools/{id}/schema-history` |
| 改治理元数据(风险级/adminPolicy/annotations) | `PUT /admin/tools/{id}`(风险升级级联失效授权) |
| 停用/启用 | `POST /admin/tools/{id}/disable` / `POST /admin/tools/{id}/enable` |
| 注销 | `DELETE /admin/tools/{id}`(级联清除授权;可同名复活) |
| 用户授权/撤销 | `POST /admin/grants`(`scope=permanent|conversation`)/ `DELETE /admin/grants/{id}` |
| 审计检索 | `GET /admin/audit-logs?toolFqn=&decision=&decisionSource=&from=&to=` |
