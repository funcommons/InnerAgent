## 2. 一次运行的完整生命周期

```
宿主前端                server                          宿主桥/模型
   │ POST /ia/api/v1/runs │                                 │
   │  (embed token)       │  验签→建 run→journal             │
   │◀── SSE 连接建立 ──────│                                 │
   │◀── CONTENT(首帧) ────│── 模型调用(流式) ───────────────▶│
   │◀── CONTENT ×N ───────│◀── token 流 ────────────────────│
   │                      │  模型发起工具调用                  │
   │                      │── 策略裁决(READ 放行/WRITE→确认)  │
   │◀── TOOL_CALL_STARTED─│                                 │
   │◀── 确认卡(如需) ─────│                                 │
   │   用户点确认          │── MCP 调用(X-IA-Act, 60s) ────▶│ 宿主 /ia-mcp
   │◀── TOOL_FINISHED ────│◀── 结果 ────────────────────────│
   │◀── CONTENT(续) ─────│── 带工具结果再调模型 ────────────▶│
   │◀── DONE ─────────────│  投影落库,关流                    │
```

关键契约事实(压测口径同源,`tools/k6/lib/config.js`):

- 端点 `POST /ia/api/v1/runs`,响应 `text/event-stream`;
- 事件帧:`id: "<runId>:<seq>"`,data 为 `AiChatStreamRespVO` JSON(含
  `outputType`/`createdAt`/`reasoningDurationMs` 等);
- 终态事件 `DONE`/`ERROR`/`CANCELLED` 后服务端关闭流;
- 断点续传:`GET /runs/{runId}/events` + `Last-Event-ID` 头(或 `afterSequence`
  参数),先回放后实时(replay-then-live);
- 事件 journal 每运行约 10 条(内部粒度),SSE 投影约 3 条/运行(实测口径)。

## 3. 事件流与持久化管线

```
模型/工具事件 ──▶ 事件 journal(PG ia_agent_event,可回放)
                    │
                    ├─▶ SSE 直发(同实例订阅者,内存路径)
                    │
                    └─▶ outbox ─▶ Redis 唤醒提示 ─▶ 其他实例/重连订阅者回放
```

- **journal 是事实源**:任何断线重连都从 journal 回放(`afterSequence`),不丢事件;
- **outbox** 是跨实例扇出桥(500ms 批 × 200 行);单实例部署时 SSE 直发不依赖它,
  多实例部署须关注 backlog 水位(见 [05-最佳实践/02-容量规划与观测](../05-最佳实践/02-容量规划与观测.md))。

## 4. 安全模型(接入方最关心的四件事)

1. **身份**:宿主后端持 RSA 私钥签 **embed token**(RS256),平台管理面登记公钥;
   私钥不出宿主。运行期平台回调宿主用 **act token**(`X-IA-Act`,60s 短时,受众限定)。
2. **授权**:`toolExecutionMode=DEFAULT`(读工具自动放行,写工具确认;持永久授权的
   写工具放行)或 `ALWAYS_ASK`(所有工具转确认,授权不可绕过,用于强管控场景)。
   另有 `ALWAYS_ALLOW`/`FULL_ACCESS` 两个**显式豁免档**(批量自动化,调用方在请求体
   主动选择时跳过确认)。默认档位下 WRITE 类工具调用必须用户确认;确认超时默认 24h
   自动过期。
3. **隔离**:租户 → 应用(appId)→ 用户三级;会话/运行/消息/三方 MCP 注册均行级隔离
   (越权访问一律 404,不泄露存在性)。
4. **SSRF 防护**:用户自助登记三方 MCP endpoint 时,平台拒绝本机/内网地址;
   应用级(管理面)为可信配置不受此限。

## 5. 多租户与部署形态

- 单实例:server + PG + Redis 即可;网关可选。
- 多实例:server 无状态水平扩,跨实例事件扇出走 outbox/Redis;需关注 backlog 与
  唤醒时效。
- 容量基线(本机 15 核共存形态实测,专机复测口径见容量报告
  `tools/k6/capacity-report-20260928.md`):100 并发运行 × 30min 零失败;
  ≈18KB 库/运行。
