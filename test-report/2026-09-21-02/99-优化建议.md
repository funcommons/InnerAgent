## 一、界面人性化

### 1. 「mock 后端」徽标改为真实环境状态灯 · P1
- **现状证据**:`../2026-09-21-01/assets/L2-01-应用列表.png` 右上角常驻「mock 后端」徽标;R1/R2 全部管理站截图均在真服务模式下顶着 mock 徽标,用户无法分辨当前数据真伪。
- **成熟平台做法**:Vercel/Linear 顶部为**环境切换器**(Production/Preview)或连接状态点(绿=已连接,实时健康);阿里云控制台页头明示当前 Region/账号,不做静态装饰性标签。
- **建议方案**:徽标改为由 `api` 层健康探测驱动的状态灯(真实服务=绿点「已连接」;msw/离线=黄点「演示数据」),构建期 `import.meta.env` 注入默认态,运行期以最后一次请求成败校正。
- **收益**:消除「看真数据却以为在 mock」的信任损伤;给支持/排障提供第一眼环境判据。

### 2. mock 域页面(熔断/Webhook)补齐或「未实现」占位 · P1
- **现状证据**:`../2026-09-21-01/assets/L7-01-熔断页-真服务模式表现.png`、`L7-02-Webhook页-真服务模式表现.png`:两页操作全部 404 失败,仅靠 #1 的误导徽标「解释」;R2 `assets/L7-…`(07-mockdomains 两用例)维持 404。PRD 中终态 Webhook 为 P1 能力(§6.1.2)。
- **成熟平台做法**:GCP/AWS 对未开通功能显示「Not yet available / 申请试用」占位页并**隐藏或置灰入口**,绝不给可交互但必败的表单;Stripe 对未配置项给引导式空态。
- **建议方案**:短期——路由表按「服务端能力清单」(可由 admin 字典端点下发)过滤菜单,未实现项置灰 + tooltip「服务端未实现」;中期——Webhook 页接 18b 已落库的 `ia_webhook_delivery`(deliveries 观测面其实有数据底座,仅差查询端点)。
- **收益**:消灭「点了必败」的死路;Webhook deliveries 端点补齐后 PRD P1 能力直接可视化,投入小。

### 3. Element Plus zh-cn locale 全量接入 · P1
- **现状证据**:`../2026-09-21-01/assets/L5-01-审计分页-第1页10行.png`:中文界面里分页显示「Total 12」;确认框按钮英文 OK/Cancel(`helpers/support.ts confirmBox` 为此做了双语兼容)。
- **成熟平台做法**:Ant Design Pro 默认 `<ConfigProvider locale>` 全组件注入;Vercel Dashboard 无一处未本地化文案。
- **建议方案**:`app.use(ElementPlus, { locale: zhCn })` 一行 + 全局文案审查清单;R2 侧 `confirmBox` 双语兼容可随后移除(测试基建同步)。
- **收益**:一行级成本消除全站「中式英文」混排;管理站整体观感直接对齐国内成熟中后台。

### 4. 上传超限 500 → 413/400 + 可读文案 · P1
- **现状证据**:`assets/L9-09-25MB超限-UI错误反馈.png`、`L9-09-25MB错误反馈文案.txt`:>20MB 触发 `MaxUploadSizeExceededException` → 500「服务器内部错误」,用户被暗示「系统坏了」。
- **成熟平台做法**:GitHub/Slack 上传超限返回 413 + 精确文案「超过 25MB 上限」并标注上限数值;Stripe 错误体永远带 `doc_url`。
- **建议方案**:GlobalExceptionHandler 增加 `MaxUploadSizeExceededException → 413`,文案携带实际上限(`spring.servlet.multipart.max-file-size`);SDK composer alert 透传该文案。
- **收益**:把「系统故障」变「使用指引」;削减支持工单。

### 5. 断流中「连接中断,自动重连中…」静默提示 · P1
- **现状证据**:`assets/L8-03-断流中UI错误态文案.txt`、`L8-03-断流中-UI状态.png`:断流瞬间暴露原始错误「network error」+「重试」按钮(数秒后自动重连成功又自行消失)。
- **成熟平台做法**:Figma/Linear 断网时显示顶部横幅「Connection lost — reconnecting…」带旋转指示,恢复即消失,从不让用户手动重试一个马上会自愈的失败。
- **建议方案**:SDK store 区分「可自动恢复的传输错误」与「终态失败」:前者渲染非阻断式「连接中断,自动重连中…」(抑制手动重试按钮),仅重连耗尽才升级为错误终态。
- **收益**:消除自愈型故障的恐慌与误操作;AI 对话流的连续感明显提升。

### 6. 轮换对话框「宽限期未实现」过时告警纠正 · P1
- **现状证据**:`../2026-09-21-01/assets/L2-06-轮换对话框(过期文案).png`:告警称宽限期语义未实现,而服务端 V9 已实现 72h 双公钥验签宽限(R2 L2-07 响应亦回 `signKeyRotatedAt`)。
- **成熟平台做法**:GitHub 的 rotating secrets 对话框精确说明「旧凭据在 N 小时内仍有效」;Vercel 轮换环境变量时明确双活窗口。
- **建议方案**:对话框文案改为「旧公钥保留 72 小时验证宽限,期间双公钥并存」并与 V9 常量同源(注释互相引用)。
- **收益**:用户敢于在业务高峰轮换密钥;文案与实现不再互相打脸。

### 7. 审计时间筛选「即输即查」修复 · P1
- **现状证据**:`../2026-09-21-01/assets/L5-03-时间过滤-UI未触发请求(发现项).png`:手输时间不触发查询(value-format 字面 `Z` 解析失败),UI 不可操作;R2 `L5-03-时间过滤-*.png` 同现象(API 直调 5.2s 用例通过,UI 键入路径仍不触发)。
- **成熟平台做法**:AntD `RangePicker` + `onChange` 即触发;Grafana 时间选择永远给出合法落点并回显生效区间。
- **建议方案**:el-date-picker 换 `value-format="YYYY-MM-DDTHH:mm:ss"`(去 Z)或改用 `@change` 取 Date 对象序列化;输入合法即查询并回显「已应用时间范围」chip。
- **收益**:审计检索的核心过滤路径从「仅 API 可用」恢复为 UI 可用。

### 8. 附件 url 传输回退 UI 提示 · P2
- **现状证据**:`assets/L9-08-15MB传输回退.json`:>10MB 且模型支持 url 传输时静默回退,UI 无任何说明;「公开可访问存储」的 url 语义对本地部署用户是隐式契约。
- **成熟平台做法**:Slack/Notion 对大文件上传明示「将以链接形式发送」;Linear 上传超限直接给限制说明。
- **建议方案**:回退发生时 composer chip 上加小字「大文件将以 URL 引用传输」;文档补 url 传输的存储可达性要求。
- **收益**:消除「附件到底发出去没有」的疑虑;部署者提前知晓存储前置条件。

### 9. 空态设计(未实现页面/表格空态/CTA) · P2
- **现状证据**:`../2026-09-21-01/assets/L7-01-熔断页-空态.png`、各表格首次进入空数据态均为空白表格;新建租户首登后管理站大部分页面是「无行表格」。
- **成熟平台做法**:AntD `Empty` + 引导 CTA(「注册第一个应用」);Vercel 空项目页是一张引导卡而非空表。
- **建议方案**:统一 `<IaEmpty>` 组件(图标+一句话+主 CTA):工具 0 行→「注册第一个工具」、授权 0 行→「去工具页授权」、未实现页→「服务端能力未开通」。
- **收益**:新租户激活路径有明确下一步;空态不再像「页面坏了」。

## 二、功能合理化

### 10. 指纹/轮换展示位(列表列+详情卡) · P2
- **现状证据**:`../2026-09-21-01/assets/L2-07-轮换公钥-响应.json`:服务端已回 `signKeyFingerprint/signKeyRotatedAt`,web `IaApp` 类型与列表均无展示位,用户无从核对指纹。
- **成熟平台做法**:AWS IAM/Stripe 均在密钥列表直接显示指纹前 8 位 + 轮换时间;GitHub Deploy Keys 列表即示指纹。
- **建议方案**:应用列表加「密钥指纹」列(等宽字体前 12 位 + 复制),详情卡展示 `signKeyRotatedAt`;类型同步。
- **收益**:宿主侧比对指纹从「查 API」变「看列表」;轮换操作闭环可见。

### 11. schema 历史 UI 入口 · P2
- **现状证据**:`../2026-09-21-01/assets/L3-12-schema历史.json`(仅 API 可达);R2 `assets/L3-12-schema历史.json` 同样只出 API 证据;store 已有 action 无入口。
- **成熟平台做法**:Terraform Cloud/其他配置平台对「资源历史」均有时间线入口;阿里云工具变更历史是一级 Tab。
- **建议方案**:工具行操作加「历史」抽屉:时间线列出 applied/pending_review/rejected/silent_refresh + 指纹 diff。
- **收益**:DEF-02 这类指纹链路问题未来可在 UI 直接审计;BREAKING 确认链可追溯。

### 12. decision_source 下拉补 `expired` 档 · P2
- **现状证据**:`assets/L5-05-值域对比.json`:服务端字典(V8)含 expired,web 下拉缺档。
- **成熟平台做法**:Datadog/Loki 的过滤器取值一律由字典端点驱动,前后端值域天然一致。
- **建议方案**:下拉选项改由 admin 字典端点拉取(或枚举共享常量),消灭手抄枚举。
- **收益**:授权过期审计可被 UI 检索;杜绝后续新增档位再漂移。

### 13. 单工具确认卡补 scope chip · P2
- **现状证据**:`assets/L10-04-scope-chip渲染观察.json`、`L10-12-scope-chip两轮观察.json`:scope 降级 chip 仅在 ≥2 工具批量条渲染,单工具(最高频)确认场景 UI 不可检视;SCOPE_RESOLVED 数据面完整(R2 `L10-03-SCOPE_RESOLVED-detail.json`)。
- **成熟平台做法**:GitHub Actions 的审批卡把「运行环境/作用域」元数据内联在单条审批上;1Password 授权弹窗永远展示请求范围。
- **建议方案**:行内确认卡补一行 scope chip;沿用 `normalizeToolCallScope` 归一(R1 交接 §7-4),旧事件按 degraded 兜底。
- **收益**:最常见场景下用户可在批准前看见约束范围语义,确认卡信息完整。

### 14. 消息区附件渲染 · P2
- **现状证据**:`assets/L9-04-消息完成后-消息区附件渲染观察.png`、`L9-04-消息区附件渲染观察.json`:发送前 chip 有缩略图/文件名,发送后气泡仅文本,历史回放同。
- **成熟平台做法**:ChatGPT/Claude/Slack 的用户消息气泡对附件有常驻缩略图/文件卡,历史回放一致。
- **建议方案**:用户气泡模板按消息附件关联渲染缩略图(image)或文件卡(file),复用 composer chip 组件;resourceUrl 已具备(`/attachments/{id}`)。
- **收益**:多模态会话的可读性与信任感(「图到底发出去没有」);历史回放完整。

### 15. toolFqn 检索语义对齐 · P2
- **现状证据**:R1 分册 F6:占位文案写「模糊」,`ToolAuditQueryService` 实现为精确 eq;`assets/L5-02-decision过滤-服务端.json` 中检索行为可复证。
- **成熟平台做法**:Datadog 搜索框明确标注「exact」或做子串/通配;Elastic Kibana 用 KQL 显式语法。
- **建议方案**:二选一并让文案与实现一致:①实现 `ILIKE '%q%'`(审计量级可承受)+ 文案「模糊匹配」;②文案改「精确 FQN」+ 支持 `*` 通配。
- **收益**:检索预期不再落空;审计排障效率提升。

### 16. 模型表单补 textProtocol 字段 · P2
- **现状证据**:`assets/L6-06-缺textProtocol-落库形态.txt`:创建 payload 不带 textProtocol(落库空串),web 类型亦缺字段。
- **成熟平台做法**:OpenRouter/LangSmith 的 provider 配置把协议/传输选择作为显式字段并给默认值。
- **建议方案**:模型表单加 textProtocol 选择(openai 兼容/mock,默认随 platform 联动),提交与类型同步。
- **收益**:落库数据完整;为非 openai 协议接入预留正确入口。

### 17. webhookSecret 明文字段类型清理 · P3
- **现状证据**:`../2026-09-21-01/assets/L2-02-注册应用-响应.json`:服务端只回 `webhookSecretMasked`,web 类型仍声明明文字段。
- **成熟平台做法**:Stripe API 类型只暴露 masked 形态,secret 仅创建时一次性可见。
- **建议方案**:`IaApp` 类型删除明文字段,补 `webhookSecretMasked`;表单仅创建时展示一次性 secret。
- **收益**:类型即契约,杜绝未来误用明文字段。

## 三、布局仿大厂

### 18. 列表页「筛选区+批量操作+列设置」三件套 · P2
- **现状证据**:R1/R2 各管理页截图(如 `../2026-09-21-01/assets/L4-01-*.png`、`L3-02-*.png`):工具/授权/审计列表只有顶部一个搜索框 + 表格,筛选条件分散在各弹窗;无批量操作、无列设置。
- **成熟平台做法**:Ant Design Pro 列表页标准件:筛选表单区(可展开)+ 工具条(批量操作/刷新/列设置)+ 表格;阿里云控制台的标签/筛选 chip 可保存。
- **建议方案**:以审计页为试点:筛选区(decision/decisionSource/时间范围/fqn)+ 工具条(导出 CSV、列设置);再抽象 `<IaListPage>` 组件推广到六域。
- **收益**:高频运维操作(批量撤销授权、按指纹筛工具)成本骤降;六域交互一致。

### 19. 面包屑 + PageContainer 页头范式 · P3
- **现状证据**:`../2026-09-21-01/assets/L2-01-应用列表.png` 等:页头仅标题,无面包屑/副标题/页级操作区;详情与列表层级靠侧栏高亮表达。
- **成熟平台做法**:AntD Pro `PageContainer`(面包屑+标题+副标题+extra 操作区)是中后台事实标准;Vercel 项目内页的面包屑+页头按钮组。
- **建议方案**:布局层加面包屑(域名→页名),页头右侧放页级操作(如工具页「注册工具」),与行内操作分级。
- **收益**:深层页面(工具详情/历史抽屉)方位感;操作分区清晰。

### 20. 分页器本地化 + pageSize/快速跳页 · P3
- **现状证据**:`../2026-09-21-01/assets/L5-01-审计分页-第1页10行.png`:「Total 12」英文 + 仅前后翻页;#3 修复 locale 后仍缺 pageSize 切换。
- **成熟平台做法**:AntD Pagination 标准四件:总数/pageSize 选择/快速跳页/上一页下一页;Datadog 日志分页支持每页 50/100/200。
- **建议方案**:统一分页组件参数(`show-total/show-size-changer/show-quick-jumper`),审计/工具/授权三表接入。
- **收益**:大体量审计数据的翻页效率;与 #3 一起构成完整本地化。

### 21. 相对时间 + tooltip 绝对时间 · P3
- **现状证据**:各列表时间列展示原始 datetime(如 `assets/L4-01-授予permanent-列表.png` 的授权时间),长字符串挤占列宽,且无相对语义。
- **成熟平台做法**:Linear/Vercel/GitHub 全面使用「3 minutes ago」+ hover 显示完整时间戳。
- **建议方案**:`<IaTime>` 组件:默认相对时间,tooltip 绝对时间(ISO+时区),列表/详情统一替换。
