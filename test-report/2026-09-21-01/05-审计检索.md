## 数据策略说明(可复跑口径)

- 真实写路径:固定工具 `e2e_audit_tool` 的授予/撤销(审计由服务端代码落库);
- 检索面合成行:psql 直插 `ia_audit_log`(FQN 固定 `mcp__e2eaudit__pag/den/time/secret`),其中 secret 行**故意以明文写入** password/api_key/nested.refreshToken —— 服务端为「读时脱敏」设计(存量原文行同样受保护),恰好验证读侧防线;写时脱敏的完整覆盖归 T2 SDK 确认线。

## 发现项

1. **UI 时间筛选不可用**(FIND-P2):`el-date-picker` 的 value-format 为 `YYYY-MM-DDTHH:mm:ss[Z]`(字面 Z),键入完整串后不触发任何查询请求(4 秒观察窗无请求,`L5-03-时间过滤-UI未触发请求(发现项).png`)→ 时间过滤在 UI 上不可操作,仅 API 可用。修复意见:改 value-format 为服务端无歧义格式(如 `YYYY-MM-DDTHH:mm:ss`,不带字面 Z),或换用 `daterange` + 显式「应用」按钮;服务端 `@DateTimeFormat(iso=DATE_TIME)` 对带 Z/不带 Z 均可解析(已验证 200),无需服务端改动。
2. **web decision_source 缺 expired 档**(FIND-P3):服务端字典(V8)含 `expired`(确认等待超时),`stores/audit.ts DECISION_SOURCES` 未跟进 → 该来源的审计行在 UI 只能裸显 code。修复意见:下拉与映射表补 `expired: 已过期(确认超时)`。
3. **toolFqn 占位文案「模糊」与实现不符**(FIND-P3):查询为精确 `eq` 匹配(`ToolAuditQueryService`),UI 占位却写「工具 FQN(模糊)」。修复意见:改占位为「工具 FQN(精确)」或服务端改 like。
4. **安全观察(设计取舍,不计缺陷)**:`params_masked_json` 落库为原文、检索端点读时统一脱敏(`AuditParamMasker` 类注释已写明取舍)。本次实证库内确为明文(`L5-04-脱敏-库内原文.txt`)——库层访问控制成为唯一防线,建议 T2 后评估写时脱敏改造。
