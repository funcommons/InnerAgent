# 运维手册 · 01 部署与配置

> 覆盖:组件清单、端口、环境变量、依赖服务、健康检查、分布式追踪、升级注意。

## 1. 组件与端口(默认)

| 组件 | 端口 | 必需? | 说明 |
| --- | --- | --- | --- |
| inneragent-server | 18090 | ✅ | 平台全部逻辑,唯一有状态组件 |
| PostgreSQL | 35432 | ✅ | journal/投影/审计/模型登记 |
| Redis | 36379 | ✅ | 会话态/outbox 唤醒 |
| 网关(静态+反代) | 18081 | 可选 | `web/dist` + `/ia` → 18090(`node e2e/gateway.mjs` 形态) |
| 宿主后端/前端 | 自定 | 接入方 | demo 为 9300/9203 |

本地开发依赖一键(叠加端口覆盖层,得到 35432/36379;只起 `docker/dev-compose.yml`
时宿主端口为 15432/16379):

```bash
docker compose -f docker/dev-compose.yml -f scripts/dev-compose.e2e-ports.yml up -d
```

## 2. server 环境变量

| 变量 | 必需 | 说明 |
| --- | --- | --- |
| `IA_ADMIN_KEY` | ✅ | 管理面密钥(请求头 `X-IA-Admin-Key`);**生产用强随机值并轮转** |
| `IA_REDIS_PORT` | ✅ | Redis 端口(与部署对齐,默认 compose 口 36379) |
| `IA_CORS_ALLOWED_ORIGINS` | ✅(有前端时) | 允许来源逗号分隔(如 `http://localhost:9203,http://localhost:18081`) |
| 首次启动 | — | 交互式引导创建管理员账号(本地口径 `admin`/`Admin#12345`) |
| `local` profile | 可选 | `allow-anonymous-demo=true`:开放 `X-IA-Demo-User` 演示头(**仅联调环境**) |

## 3. 数据库

- 库名/用户随 compose(`inneragent`/`inneragent`);
- 容量:≈18KB/运行 + journal ≈10 事件/运行(实测口径)→ **规划归档/分区**;
- 多应用部署注意:平台级表(`ia_ai_model`/`ia_model_api_config` 等)不受租户/
  应用行级注入约束,属全局配置;
- 观测:`pg_stat_user_tables` 序扫基线见容量报告 §4(空表高频序扫为已知观察项,
  不阻塞)。

## 4. Redis

- 策略 `noeviction`(平台数据不靠淘汰);水位极低(峰值个位数 MB);
- `outbox` 唤醒提示经 Redis:多实例部署关注 `outbox_backlog` 指标
  (见 [05-最佳实践/02 §4](../05-最佳实践/02-容量规划与观测.md))。

## 5. 健康检查与启停顺序

```bash
curl -s http://localhost:18090/actuator/health      # UP
curl -s http://localhost:18090/actuator/prometheus | grep outbox_backlog
```

启动顺序:PG/Redis → server → (可选)网关 → 宿主后端(桥注册)→ 宿主前端。
**停机**:先摘流量(网关),等 `runs_active` 回落(在途运行自然收尾或由客户端
重连追平 —— journal 保证不丢),再停 server。

## 6. 分布式追踪(OTel GenAI spans)

平台内建 GenAI 语义 span 桥(命名空间 `com.inneragent.genai`),四类挂点:

| 挂点 | 位置 | 采集内容 |
| --- | --- | --- |
| `invoke_agent` | 运行监督(run 入口/子 Agent) | agent id/name、root/child、`inneragent.run.id` |
| `chat` | 模型调用守卫层 | 模型名、`finish_reason`、token 用量(input/output/缓存/推理) |
| `execute_tool` | 平台工具适配器 | 工具名/描述/调用 ID、风险级别 |
| MCP `tools/call` | 宿主 MCP 客户端 | MCP server key、调用 ID |

属性键对齐 OTel GenAI 语义约定:`gen_ai.request.model`、`gen_ai.usage.input_tokens`、
`gen_ai.conversation.id`、`gen_ai.agent.id`、`inneragent.run.id`、`inneragent.app.id` 等。

**隐私口径**:prompt/completion 内容默认**不采集**(仅元数据与用量,对齐审计脱敏);
`inneragent.observability.genai.capture-content=true` 显式开启后才有内容摘要,且按
`content-max-chars`(默认 512)截断。生产建议保持默认关闭。

### 6.1 激活路径(二选一)

| 路径 | 做法 | 说明 |
| --- | --- | --- |
| a) OTel javaagent(零配置) | 启动命令挂 `-javaagent:.../otel-javaagent.jar` | 服务经 `GlobalOpenTelemetry` 发 span,agent 在场即自然生效,平台零配置 |
| b) 内置 OTLP 直配 | 配 `inneragent.observability.otlp.endpoint` 即启用 | 服务内自建 SDK 异步导出,见 6.2 |

两者都不配 = noop 工厂,零行为变化。

### 6.2 内置 OTLP 直配(`inneragent.observability.otlp.*`)

| 配置键 | 默认 | 说明 |
| --- | --- | --- |
| `endpoint` | 空(不导出) | OTLP/HTTP traces 地址(如 `http://otel-collector:4318/v1/traces`);未配 = 零行为变化 |
| `timeout-ms` | 10000 | 单次导出超时(毫秒);BatchSpanProcessor 异步导出,不阻塞 span end |
| `headers` | 空 | 附加请求头 Map(如 `headers.authorization: Bearer xxx`) |
| `sample-ratio` | 1.0 | 根 span 采样比例(0<r≤1,TraceIdRatioBased);非法值拒绝启动 |

- 导出形态 OTLP/HTTP(span),`service.name=inneragent`;容器关闭时 flush 兜底;
- **双管线注意**:endpoint 与 javaagent 同时在场时,服务内 SDK 优先、全局注册
  降级跳过(span 仍走服务内 bean,不破链路)——建议二选一,避免重复导出。

### 6.3 与 Prometheus 指标的关系

两条独立管线:§5 的 `/actuator/prometheus` 是 metrics(Micrometer),本节是
traces(OTLP),互不依赖、可单独激活。traces 不通时先验证 4318 口:

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://otel-collector:4318/v1/traces
```

本地验证用一行 collector(Jaeger all-in-one,OTLP 入口 + UI):

```bash
docker run --rm -p 16686:16686 -p 4318:4318 jaegertracing/all-in-one:latest
```

## 7. 升级注意

- 事件 journal 是事实源:升级期间进行中的运行升级后可经 `Last-Event-ID` 续传;
- 模型 `config`/mock 脚本变更即时生效,无需重启(注意 mockScript 必须嵌在
  `config.mockScript` 键下);
- 三方 MCP 注册变更自动广播失效,无需重启;裁剪部署(无 invalidator)静默跳过。

## 8. 备份与恢复要点

- 必备表:运行/会话/事件 journal/审计/模型登记(全库备份最简);
- Redis 可丢失重建(会话态短暂回退,重连自愈);恢复后以 journal 为准。
