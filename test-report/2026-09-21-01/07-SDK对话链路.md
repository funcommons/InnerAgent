## L7-01 · Shadow DOM 双向隔离与主题令牌穿透

- 步骤:打开 demo-host(宿主故意放置激进全局样式:红色段落/绿色虚线按钮/品红 textarea);断言组件内容位于 shadowRoot;取组件内按钮/输入框与宿主按钮/段落的 computedStyle 对比;点击宿主「切换主题」按钮后读组件内 `--ia-primary/--app-primary` 计算值。
- 期望:组件不受宿主样式污染;宿主样式不被组件覆盖;`--ia-*` 令牌在宿主元素覆写后穿透 Shadow 边界生效。
- 实际:全部符合。shadowRoot 存在且组件窗口渲染其中;组件按钮背景/边框非宿主绿虚线,输入框边框非品红;宿主按钮保持 `rgb(46,125,50)`+dashed+黄字,宿主段落保持红色斜体;主题切紫后组件内 `--ia-primary/--app-primary` 计算值同为 `#7c3aed`。
- 判定:✅ 通过
- 证据:`L7-01-ShadowDOM隔离-初始(宿主绿虚线+组件SDK样式).png`、`L7-01-主题令牌穿透(紫色实时换肤,宿主按钮不受影响).png`

## L7-02 · 发消息 → SSE 流式增量渲染(中间态+终态)

- 步骤:独立演示用户注入(`X-IA-Demo-User`,经 Playwright 路由);发送「现在几点了?」;捕获停止按钮、live 内容长度(t1/t2 间隔 1.5s)、终态标题;页面内 fetch 包装捕获 POST /runs 的 SSE 响应体;psql 核对 run 状态。
- 期望:流式增量可见(内容增长)、终态「已完成」、SSE id 严格递增且与库一致、工具 chip 渲染。

- 判定:✅ 通过

## L7-07 · DEF-05 取证:默认 baseURL 下 SDK http 层双重拼接 → 模型/会话全 404

- 步骤:按 demo-host README 口径接入(baseURL 默认 `/ia/api/v1`),打开页面并收集全部 `/ia` 网络往返。
- 期望(契约):`GET /ia/api/v1/me/models?type=1` 等应 200。
- 实际:SDK `client.ts request()` 内部拼 `getBaseURL()`,而 `me.ts/conversations.ts/runs.ts(查询端)/attachments.ts` 调用点又自带 `${getBaseURL()}${path}` → 实际请求 `/ia/api/v1/ia/api/v1/me/models?...` 全部 **404**;UI 后果:输入区常驻「请求的资源不存在」、输入框与发送按钮禁用,**demo-host 默认接入形态不可用**。唯一不受影响的是 SSE `POST /runs`(authenticatedFetch 单次拼接)。
- 判定:❌ 缺陷 → **DEF-05(P1)**,修复意见见分册。
- 证据:`L7-07-DEF05-demo-host默认接入-模型404-发送禁用.png`、`L7-07-DEF05-双重拼接404请求.json`
