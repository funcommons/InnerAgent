# 接入指南 · 05 模型接入与切换

> 适用:接入自有模型、切换默认模型、以及用 canned mock 模型做测试/演示。

## 1. 模型登记模型

模型登记在 `ia_ai_model`(平台级,全局可见;应用不各自维护模型清单):

| 字段 | 说明 |
| --- | --- |
| `code` | 模型唯一标识(如 `mock-text`) |
| `model_type` | 类型档(1=对话);默认模型按类型解析 |
| `default_model` | 同类型是否默认(**同类型只应有一个**) |
| `status` | 1=启用 |
| `sort` | 排序(缺省候选顺序) |
| `max_concurrency` | 该模型并发闸(压测/大流量必须调高,默认 5) |
| `config` | 供给方的 JSON 配置(密钥/baseUrl/mockScript 等) |

运行时解析顺序:**请求指定 `modelId` > 该类型 `default_model=TRUE AND status=1
ORDER BY sort LIMIT 1`**。

> 对应的 API 配置(密钥等)在 `ia_model_api_config`,同为平台级表。

## 2. 接入 OpenAI 兼容模型

1. 管理面/API 登记模型行(baseUrl + apiKey 落 `config`,密文);
2. `max_concurrency` 按供应商限流设置(平台会排队而非击穿供应商);
3. 设 `default_model=TRUE`(先取消原默认,避免双默认歧义);
4. 用一段带工具的对话验收 tool-calling 生效(模型不支持 function-calling 时工具
   永不触发,这是最常见的"接入成功但不调工具"原因)。

## 3. canned mock 模型(测试与演示利器)

`MockAiProvider` 两种形态:

**① rounds 遗留形态**(按轮次脚本出字)—— 简单演示用。

**② rules 规则形态**(推荐,CI/压测同源):

```json
{ "mockScript": {
    "deltaMs": 800,
    "rules": [
      { "match": "帮我建一张工单：标题=(.+?)，描述=(.+?)，优先级=(\\w+)",
        "tool": "create_ticket",
        "args": { "title": "$1", "description": "$2", "priority": "$3" } },
      { "match": "年假|假期|请假", "reply": "根据知识库…[KB:demo-kb-annual-leave]" }
    ],
    "default": "我是 ACME 演示助手…"
} }
```

行为口径(与单测同源):

- 规则按序匹配**最后一条非空用户消息**;`match` 是正则,`$1..$9` 捕获注入
  `tool.args` 或 `reply`;
- `tool` 写短名即可,平台按工具箱 FQN 后缀(`__<name>`)解析 —— 宿主桥/三方 MCP
  工具都能被脚本驱动;
- 工具阶段只在"用户消息之后尚无工具结果"时触发(避免续写轮重复调工具);
- 无规则命中 → `default` 回复;
- `deltaMs` 为出字节拍(压测时是事件率的主要决定因素,容量报告须记录取值)。

> **两个坑**(实录,2026-09-28):
> ① 规则对象必须嵌在 `config.mockScript` 键下 —— 写成裸对象会静默回退遗留形态;
> ② 改 `config` 后用 `ia_agent_run.kernel_spec` 的 modelOptions 核对生效值。

## 4. 切换/回切默认模型(压测→常态)

```bash
# 切 mock(mock-model-script.sql):置 default + 降其余默认
docker exec -i inneragent-postgres psql -U inneragent -d inneragent \
  < examples/acme-demo/seeds/mock-model-script.sql

# 回切真实模型
docker exec -i inneragent-postgres psql -U inneragent -d inneragent \
  < examples/acme-demo/seeds/mock-model-restore.sql
```
