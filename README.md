# InnerAgent
应用内嵌智能体微服务

只服务本应用的内嵌式 AI Agent 微服务系统，通过 MCP 操控应用，支持 SKILL、提示词、上下文与无向量 mini 知识库。

极简接入

1. 创建配置Agent 
2. 应用开内部 mcp服务,并内部注册为tools
3. 前端WEB 引入 js sdk
4. 前端给出 用户,当前页,当前对象 信息
5. Agent 反查 APP 得到 约束范围
6. SDK 接入渲染微前端: 对话页,记录页,配置页 可配样式,主题,颜色
8. 用户对话,可以通过mcp操作 app
9. 注册三方应的mcp,可以实现基于 Agent的数据打通

用例: 
  用户 #12993的 密码改为test123; 
  这个产品的简介优化一下; 
  创建一个新的 流程,以 #3432 流程为模板, 加上用户退款流程
  用我上传的聊天记录,创建一份合同, 甲方是XXX公司,同时创建这个商户.

## 附件传输方式与存储可达性要求(部署前置条件)

对话附件(图片/文件)有两种传输方式,由附件大小与对话模型能力共同决定:

| 传输方式 | 大小上限 | 语义 |
| --- | --- | --- |
| `base64` | ≤ 10MB | 文件内容内联进模型请求 |
| `url` | ≤ 20MB | 文件以**引用链接**进入模型请求,由**模型提供方主动拉取** |

**url 传输的存储可达性要求(部署方必须提前确认)**:

1. `url` 传输的 `resourceUrl` 是 API 根相对路径(`/attachments/{id}`),
   SDK `resolveMediaUrl` 会拼接待配置的 `baseURL`(默认 `/ia/api/v1`)形成完整地址。
   **模型提供方(而非浏览器)需要能 HTTP GET 到这个地址**——
   即 InnerAgent 的 API 必须以模型服务商网络可达的地址暴露:
   公有云模型要求公网域名/IP;私有化模型要求与其同网段的可达地址。
   以 `localhost`/内网回环地址接入外部模型时,`url` 传输的附件将拉取失败。
2. 因此,接入外部 SaaS 模型且需要传大附件时,请将 InnerAgent 部署在
   具备公网可达入口的环境(反代 + 域名 + TLS),并将 SDK `baseURL`
   配置为该公网绝对地址;纯内网部署建议改用支持 base64 传输的模型,
   或自建与模型同网段的对象存储工作空间(`ia_storage_config` 的
   `object_storage` 后端)并暴露可达读址。
3. 附件正文落 `ia_agent_workspace_config` 指定的三后端
   (database / local / object_storage);选择对象存储后端时,同样需要保证
   该存储桶的读地址对模型提供方可达(签名 URL 或公共读)。

一句话:**`base64` 上限 10MB 之内开箱即用;超过 10MB 走 `url` 引用传输,
前提是「模型能访问到你的 InnerAgent API」——这是部署前置条件,不是运行时报错项。**
