## 裁决一:yml 静态 MCP 双通道并存

**背景**:AgentScope 内核原生的 MCP 接入是配置文件驱动的静态注册表;InnerAgent 的主链路则是管理面注册(`ia_tool_registry` → `endpoint_url` → 懒建 MCP 客户端)。两套来源都能向内核供给 MCP 工具,若不做边界划分,会出现「同义工具双入口、口径不一」的维护黑洞。

**决定**:**双通道并存、默认静态通道关闭**。通道 A:AgentScope 静态 MCP(`fusion.agentscope.v2.mcp.*`,默认 `enabled: ${AGENTSCOPE_MCP_ENABLED:false}`、`servers: {}`),由 `AgentScopeMcpRegistry` 持有真实 MCP 客户端,服务于内核级/演示场景;通道 B:宿主桥 MCP(`inneragent.mcp.*`,`enabled: true`),`McpToolCatalog` 聚合 `ia_tool_registry` enabled 条目,经 `McpClientToolInvoker` 按 `(appId, endpoint_url)` 懒连、act token 鉴权调用。内核可用 MCP 工具面取**两通道并集**,注册表条目以确定性 FQN `mcp__<serverKey>__<toolName>` 进入白名单;SDK 请求体 `enabledMcpTools` 三分法(`null`/`[]`=默认可见,非空=显式白名单,DEF-07 修复语义)对并集生效。

**影响**:接入方宿主工具只走通道 B,不需要也不应该去配 `fusion.agentscope.v2.mcp.servers`;静态通道默认关闭意味着裸部署不会有幽灵工具。出处:`inneragent-server/src/main/resources/application.yml`(两段配置)、`agent/mcp/AgentScopeMcpRegistry.java`、`agent/mcp/McpToolCatalog.java`、`agent/kernel/AgentKernelSpecFactory.java`(并集注释)。

## 裁决二:紧急停用语义边界(不批量取消;limits 管理面待内核接线)

**背景**:《02-技术方案》§4.7 早期表述为「紧急停用生效延迟 ≤5s(经 Redis 取消通道)」,并承诺全套资源上限(并发 8/QPS 20 等)强制执行。P2 实装时按「最小实现」收口,旧契约字样已在 R3 复盘后从代码与文案中清除(OBS-R3-2,提交 `27f9d9e`)。

**决定**:(1)**应用级总开关只拒新 run**:停用后发起 run/续跑在入口 `assertRunStartAllowed` 处 403「应用已紧急停用:…,新运行已被拒绝,请等待管理员恢复后再试」;**不提供批量取消**,进行中的 run 需管理员逐个 `POST /ia/api/v1/admin/circuit-breaker/terminate-run`(复用取消通道至 `CANCELLED`,审计 `run-terminated/forced-policy`)。(2)**资源上限七字段(默认并发 8/QPS 20)仅落库与管理面读写**(部分合并保存,值域校验 400),**内核执行层接线待后续**——当前真实生效的运行时护栏只有总开关与内核固有的 `run-timeout 30m / confirmation-timeout 24h / ingress 4096 事件×8MB`。本版不强行重构内核加并发/QPS 挂点。

**影响**:运维 SOP 必须按「停开关 → 查 activeRuns → 逐个 terminate-run → resume」执行,不得假设停用即全停;接入方不得依赖 `mcpConcurrency/mcpQps` 做容量保护,须在宿主工具侧自行限流(PRD 护栏指标的宿主侧二次限流要求)。出处:`platform/circuit/CircuitBreakerLimits.java`、`server/admin/CircuitBreakerAdminService.java`、`server/admin/AdminCircuitBreakerController.java`、`agent/kernel/AgentScopePipelineRunService.java`(403 调用点)、迁移 `V14__circuit_breaker_and_webhook_config.sql` / `V15__ia_app_circuit_limits_text.sql`(`ia_app.circuit_stopped` 列注释「进行中 run 需管理员逐个 terminate-run」)、`test-report/2026-09-21-04/00-R3验证报告.md`(R4-03/04 实证)。

## 裁决三:错误语义表统一(以 GlobalExceptionHandler 为唯一口径)

**背景**:R1~R2 轮实测暴露错误反馈的「系统故障化」问题:上传超限返回 500「服务器内部错误」、约束冲突裸抛 500、各域文案各说各话(优化建议 #4/#17)。接入方与用户都无法从错误体得到「下一步做什么」。

**决定**:**全服错误语义以 `GlobalExceptionHandler` 及其内嵌 `ErrorSemantics` 枚举为唯一口径**,统一信封 `{"code","msg","data"}`,关键映射为:`BusinessException` 按业务码透传;参数/请求体类错误(校验失败、JSON 不合法、缺参、类型错、`IllegalArgumentException`)→ **400**;`HttpRequestMethodNotSupportedException` → **405**;`DataIntegrityViolationException`(未在服务层预判的唯一性/完整性冲突)→ **409**;`MaxUploadSizeExceededException` → **413**(文案携带实际上限,读自 `spring.servlet.multipart.max-file-size`);`ResourceAccessException`(上游连接失败/超时)→ **502**。每条文案附带行动指引(「请刷新后重试」「请压缩或拆分文件后重新上传」等)。SSE/长连接的客户端断连(`Broken pipe` 等)按正常断流静默,不回错误体。

**影响**:接入方错误处理只需对着一张表(《接入指南》§6.5);两个易错点由此定案——附件业务超限(base64>10MB / url>20MB)是 **400** 而非 413,只有 multipart 硬限超限才是 413;管理面密钥未配置时管理面整体 403 默认关闭。出处:`platform/common/GlobalExceptionHandler.java`(含 `ErrorSemantics`)、`platform/common/CommonResult.java`、提交 `dfcecb5`(上传 413 + 错误语义表)、`test-report/2026-09-21-02/99-优化建议.md` #4/#17。

## 裁决四:附件传输约定(base64 ≤10MB / url ≤20MB + 存储可达性前置)

**背景**:对话附件的传输方式由附件大小与对话模型多模态能力共同决定;url 引用传输的拉取方是**模型提供方而非浏览器**,这一隐式契约在早期部署中反复被忽略(内网部署 url 附件静默拉取失败)。

**决定**:(1)`base64` 传输单件 ≤ **10MB**(超限 400「base64 传输附件大小不能超过 10MB」,常量 `AiModelMultimodalCapabilities.MAX_BASE64_INPUT_BYTES`);`url` 传输放宽至 ≤ **20MB**(超限 400);multipart 硬限单文件 20MB/请求 25MB,超限 **413**(见裁决三)。(2)url 传输为**部署前置条件**:InnerAgent API(或对象存储读址)必须对模型提供方 HTTP 可达——公网 SaaS 模型需公网入口,内网部署改用 base64 或与模型同网段的对象存储工作空间(`ia_storage_config` 的 `object_storage` 后端)。(3)附件正文落 `ia_agent_workspace_config` 三后端 `database / local / object_storage`;读取端点 `GET /ia/api/v1/attachments/{id}` 带归属校验,非本人一律 404(不泄露存在性)。

**影响**:接入方在部署评审阶段就要确认 url 传输的可达性(这是配置问题,不是运行时报错项);SDK `resolveMediaUrl` 以 `baseURL` 前缀拼 `/attachments/{id}`(默认 `/ia/api/v1`),跨域部署时 `baseURL` 须配模型与浏览器都可达的绝对地址。出处:根 `README.md`「附件传输方式与存储可达性要求」、`agent/attachment/AgentAttachmentService.java`、`server/controller/AgentAttachmentController.java`、`model/config/AiModelMultimodalCapabilities.java`、`application.yml` `spring.servlet.multipart` 段、`agent/workspace/AgentWorkspaceBackend.java`、`sdk-js/packages/core/src/mediaUrl.ts`。
