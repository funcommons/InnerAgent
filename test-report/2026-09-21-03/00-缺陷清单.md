## DEF-08 · ia_app 行任何 UPDATE 全链 500(P1,服务端回归)

- **现象(全部亲测复现,证据见 assets/)**:
  | 端点 | 结果 | 证据 |
  | --- | --- | --- |
  | `PUT /admin/circuit-breaker/limits` | 500 | `R3-02-PUT-limits.json` |
  | `POST /admin/circuit-breaker/emergency-stop` | 500 | 会话记录(探针 `R3 手验-探针`) |
  | `POST /admin/circuit-breaker/resume` | 500 | `R3-03-POST-resume-500.json` |
  | `PUT /admin/webhooks/config` | 500 | `R3-12-webhook-config-PUT.json` |
  | `PUT /admin/apps/{id}`(**公钥轮换**) | 500 | e2e `test-results/02-apps-公钥轮换-*/trace.zip` + spec 02 用例失败 |
- **根因**:`dfcecb5` 给共享实体 `AppRegistration` 新增 `circuit_limits_json`(PG **JSONB**)列并标注 `@TableField(typeHandler = JsonbTypeHandler.class)`,但 `JsonbTypeHandler.setNonNullParameter` 实为 **MySQL JSON 处理器**(`ps.setString`,见 `platform/common/handler/JsonbTypeHandler.java`),对 PG jsonb 列发出 varchar 参数 → `PSQLException: column "circuit_limits_json" is of type jsonb but expression is of type character varying`。`autoResultMap` 使 SELECT 能读出该列(非 null)→ **任何** `updateById(ia_app)` 都会把该列带进 SET 子句 → 全部 ia_app 写路径阵联。
- **为什么单测没拦住**:`AdminCircuitBreakerApiTests`/`CircuitBreakerAdminServiceTests` 均 Mockito 切片,service/mapper 层被 mock,真实 PG 写路径不在覆盖内(failsafe/surefire 全绿与实况脱节)。
- **影响面**:
  1. 熔断域三写端点 + Webhook 配置保存全部不可用(优化建议 #2 服务端半「写半」实为 0 可用;读路径正常);
  2. **REGRESSED**:R2 全绿的「公钥轮换」(spec 02 L2-06/07)被打挂——应用编辑/轮换属既有核心管理功能;
  3. 紧急停用总开关只能经查库直设,故 R3 分册中「停用→新 run 403」守卫语义以 psql 前置完成验证(守卫本身工作正常,`R3-04/05` 证据)。
- **修复方向建议(供参考,不实施)**:JSONB 列改 TEXT;或 typeHandler 以 `PGobject`(`setValue(json, Types.OTHER)`)包装;或 JDBC URL 加 `stringtype=unspecified`。三选一后补一条**直连 PG 的 failsafe IT** 盖住 updateById 路径。
- **定级理由**:P1 —— 既有功能回归 + 新域写半全灭;数据无损(全部报错回滚)。

## DEF-09 · GET /admin/webhook-deliveries 不带 status → NPE 500(P2)

- **现象**:`WebhookDeliveryAdminService.normalizeStatus`(第 89 行)对 `status` 参数直接 `.trim()`,查询参数缺省(null)时 NPE → 500(`R3-09-deliveries-无status-500.txt`;server.log 栈:`Cannot invoke "String.trim()" because "status" is null`)。
- **连带 UI 面**:webhooks 页首载 deliveries(未选状态过滤)即命中该 500,表格空态;选择任一状态过滤后恢复 200(A05 用例已证过滤+重投本身正常)。
- **影响面**:「全部投递记录」这一最常用查询形态不可用;契约注释宣称的 `status/appId/event 过滤` 仅部分成立(status 必填语义未在文档/参数校验上表达)。
- **定级理由**:P2 —— 观测面半残,有 workaround(带 status 查询);非回归(R2 时该端点不存在)。

## 观察项(不定级,移交产品侧台账)

1. **OBS-R3-1**:terminate-run 以 `X-IA-Admin-Key` 引导通道调用时,事件/审计 `operator` 记为 `demo-user`(`R3-06-terminate-run-200.json`、`R3-06-审计-run-terminated.txt`),而非服务端注释宣称的引导缺省 `admin`(`CircuitBreakerAdminService.currentOperator` fallback)——操作者身份通道粒度需核对 AdminTokenFilter 写入 SecurityContext 的 principal 命名。
