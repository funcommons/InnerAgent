## A. 界面人性化(让人「一看就会、一用就顺」)

### A1. 确认流剧本的「确定性」保障 · P0/M
- **现状**:ticket-assistant 对话要求多轮确认(报告 L5-1 失败现场实测),演示员现场常因剧本话术偏差卡住;系统提示词设计 + ALWAYS_ASK 模式叠加,模型严格等用户明确"按 A 选项提交"。
- **对标**:Stripe Docs 的「一键可复现」+ 演示按钮标准;Linear 的「快捷操作」面板。
- **建议**:
  1. **场景画陈列「剧本」升级为「一键演示」**:点击直接深链+预填输入框+自动点击「发送」+ 自动批准确认卡;URL: `/ia/embed?agentType=ticket-assistant&script=demo-build-ticket`(query 触发自动剧本)
  2. **演示模式开关**: `?demoMode=guided` 让 EmbedChat 在工单要素缺失时给出"点击此处预填剧本第一条"的快捷条
  3. **对话页加「剧本模式」标签**:已挂载 chat 顶部加 chip:"📜 当前在演示剧本模式,点此重置对话并重演"

### A2. 对话空态与发送口径合一 · P1/S
- **现状**:SDK vendor 内部空态由 demo 端无法控制;§D2 send-hint 已加但视觉被 SDK 容器遮挡(报告 DEF-20260924-02);演示员常被「Enter 换行」「Ctrl+Enter 发送」placeholder 误导。
- **对标**:Notion AI、飞书 AI 助手 — 输入区常驻发送口径 chip;Claude.ai — 输入框底部灰字"Enter to send, Shift+Enter for new line"。
- **建议**:
  1. **send-hint 移到挂载按钮旁**:未挂载态就把发送规则亮给用户,挂载后 SDK 接管不需再提醒
  2. **SDK placeholder 改造(走 vendor)**:不指望短期内改,前端可在 WC 容器下方追加 `<p>` 提示"SDK 内置输入框,回车换行,点发送按钮提交"

### A3. 复制/重答/重试 闭环 · P1/M
- **现状**:报告 A3 已记;本次回归 L4-2 仅验证流式回复,未验证 hover 复制按钮;错误中断也无重试入口。
- **对标**:Claude/ChatGPT/Gemini 三家标配;Intercom Fin 工作台支持"重新生成答案"+"反馈理由"。
- **建议**:
  1. **气泡 hover 工具条**:复制 / 重新生成 / 反馈(👍/👎 落管理台反馈页)
  2. **错误中断友好**:对话中断时 bubble 末尾加"⚠️ 回复中断,[重试]"按钮(点击重发同一 message)
  3. **流式光标动画**:回复末尾渲染 `▍` 闪动,区分"打字中"vs"已结束"

### A4. EmbedChat 空态给「剧本提示」 · P2/S(本次新增)
- **现状**:§A1 改造后 EmbedChat 未挂载态有 5 场景 chip,但 chip 点击跳转后**对话页立刻挂载**——演示员错过"剧本第一条"提示。
- **对标**:Intercom Fin — 给空态展示 3 条对话建议;ChatGPT — 「Get started」预填剧本。
- **建议**:每个 chip 跳到画陈列对应 agentType 的剧本折叠区,带「点击此处预填对话」一键按钮,直接写入 localStorage `embed-prefill-{agentType}`,SDK init 时读取预填

## B. 功能合理化(让演示「讲得通、跑得稳」)

### B1. L5 失败的"演示兜底"路径 · P0/已记录
- **现状**:报告 DEF-20260924-01 实测;L5 失败原因是剧本设计 + 测试消息格式;**L9-1 直连工单路径仍 100% 通过**。
- **对标**:Notion/Figma — 同一功能提供"演示路径"和"使用路径",演示路径简化。
- **建议**:
  1. **「工具演示页」加 banner**:`<el-alert>` 类型 warning,文字「确认流正在演示剧本中(等模型严格多轮确认)?用本页表单直建[链接]直达」——给现场演示员 L9 兜底
  2. **侧栏图标排序**:`/ia/tools` 与 `/ia/embed` 同级,且 tools 标注"直建"区别于 embed 的"对话建"
  3. **场景画陈列卡片加"演示成功率"**:0.5 条灰字说明"实测平均 N 轮可达确认卡"

### B2. 工具演示页过滤与自动刷新 · P1/S(本次回归通过,改进)
- **现状**:工单列表 channel=agent/direct 仅以标签区分,无过滤;事件流无自动刷新开关(报告已记;L9-2 PASS 但内容有限)。
- **对标**:AWS 控制台资源列表的过滤 tab + 自动刷新开关;Stripe 事件流的 live toggle。
- **建议**:
  1. 工单列表加「全部/Agent 创建/表单直建」filter tab
  2. 事件流加「自动刷新(5s)/暂停」开关,新事件高亮 fade-in
  3. 工单行加「查看关联运行」深链,跳运行树

### B3. 工单 SLA 兑现 · P2/M(系统提示词已承诺,UI 未兑现)
- **现状**:ticket-assistant 系统提示词承诺 SLA(high 30 分钟响应、normal 2 小时、low 1 工作日),但 L5-3 工单列表不展示 SLA 字段,承诺无处核实。
- **对标**:Jira/Zendesk 的 SLA 列与倒计时。
- **建议**:工单行加「响应时限」列(按优先级换算),临期高亮;创建后实时倒计时;逾期变红。

### B4. 覆盖表管理台行直达 · P2/S(报告 D4 改进)
- **现状**:覆盖表管理台行跳 `/ia/admin` 默认 `/definitions`,未直达对应管理页(Skill/KB/MCP/模型)。
- **对标**:AWS 控制台各页顶部「Account/Region」徽标直接跳转。
- **建议**:
  1. iframe src 支持 hash 路由:`/ia/admin#/skills` `/ia/admin#/kb` `/ia/admin#/mcp-servers`
  2. 管理站 web `view="config"` SDK 改造或 hash 跳转
  3. 覆盖表行用 `<a href="http://localhost:18081/skills" target="_blank">` 直开新窗口

## C. 布局与信息架构(对标成熟控制台)

### C1. 管理台导航分组显性化 · P2/M
- **现状**:12 个导航平铺;语义分组(集成中心/数据洞察/运行治理)只存在于面包屑。
- **对标**:Linear/Vercel 侧栏分组 + ⌘K 命令面板。
- **建议**:iframe 内的管理台无法 demo 端改造;**覆盖表分组说明** 即可解决该问题:覆盖表加"管理台"分组列(集成中心/数据洞察/运行治理/工具授权)

### C2. 总览页状态卡可观测性 · P1/S(本次已修,改进)
- **现状**:§B4 修复后 Overview 有 last-checked + 重查按钮 + 失败告警。
- **对标**:AWS Console、Datadog 状态卡都有"Last checked + Auto-refresh"。
- **建议**:
  1. 加「自动刷新(30s/1m/5m/关)」开关
  2. 持续失败时徽标转红 + 失败次数累加(1次/2次/3次+ 标签区分)
  3. 成功后徽标短暂变绿闪一下(反馈信号)

### C3. 演示站浏览器标题 · P0/S(已修,微调)
- **现状**:§C3 修复后 `/ia` 路由用「ACME 接入演示」,绕开"脚手架"误字。
- **对标**:任何对外产品的 title 规范 `页面名 · 产品名`。
- **建议**:
  1. 产品名不动(app.name 不擅自动,产品决策)
  2. 加 favicon(目前用默认,品牌体验差)
  3. 公开页面 `<title>` 含产品副标语(如「ACME 接入演示 · 应用内嵌智能体微服务」)

### C4. 顶栏应用徽标常驻 · P2/S
- **现状**:管理台嵌入页无应用徽标(已天然满足);demo 侧栏无应用切换器。
- **对标**:AWS 每页顶部 Account/Region 徽标。
- **建议**:demo 顶栏加"当前应用:acme-demo (id=34)"徽标,点击跳覆盖表行(同 appKey 视角)

## E. 工程与质量保障(把本轮发现变成「不再发生」)

### E1. e2e 守卫用例标准化 · P1/M
- **现状**:报告 TR-20260923-01 与本次 TR-20260924-01 复用同一驱动脚本,改动只在 `reportDir` 路径。
- **建议**:
  1. **固化进 e2e/**:把 `demo-regression.driver.mjs` 挪到 `examples/acme-demo/e2e/` 并配 vitest/playwright runner
  2. **CI 触发**:mock 模型兜底,CI 跑 24 用例(避免依赖真模型)
  3. **PR 模板要求**:任何 demo 改动必跑 `pnpm test:e2e`

### E2. 报告归档与可对比性 · P2/S
- **现状**:每次报告按 `2026-09-XX-NN` 编号归档在 `test-report/`。
- **建议**:
  1. **results.json 标准化**:统一字段 `id/line/title/status/ms/shots/consoleErrors/httpErrors/notes`
  2. **历史对比脚本**:`test-report/diff.js` 对比两次报告的 PASS/FAIL delta
  3. **关键指标趋势**:把每次报告的「总通过率 + 各业务线 PASS 数」存 trend.json

### E3. 服务端工具面可视性 · P1/S
- **现状**:报告 DEF-02 修了 McpToolCatalog appId 串台,但**修复前没可视化告警**——只有真机对话失败才知道。
- **建议**:
  1. **管理台「应用级查看」入口**:每个应用可查本应用的工具面装配(`GET /admin/tools?appId=N`),UI 高亮"已注册 N / 启用 N"
  2. **appId mismatch 守卫**:任何写工具行(appId 不等于预期)→ 即时弹错误提示「落错应用」+ 阻塞写入
  3. **回归 IT**:本轮 95e2a89 加的 `ToolRegistryAdminAppScopeIT` 9 用例固化为 CI 必须跑

### E4. 系统提示词版本化 · P2/S
- **现状**:ticket-assistant 提示词"在你确认前,我不会调用 create_ticket"——演示现场常卡。
- **建议**:
  1. **种子包 prompt 模板**:从 agent-bundle.json 抽离到独立文件 `seeds/prompts/*.md`,版本号化
  2. **demo 专用 mode 标签**:提示词 meta 加 `demoMode: "aggressive"`,在该模式下覆盖剧本严格度
  3. **A/B 演示模式**:管理面 UI 提供"演示模式开关"全局切"aggressive/standard",agent-bundle.json 跟着

### E5. 真实压测回填容量报告 · P3/L(遗留)
- **现状**:k6 压测脚本就位,真实压测未跑。
- **建议**:跑一次 30min steady + 1000 idle + 500eps ramp 三场景,生成容量报告(基线对比)
