# API 参考 · 02 错误码与重连语义

> 口径与平台单测同源(`CommonResult.code` + message)。HTTP 状态与业务码一致。

## 1. 错误码速查

| 码 | 语义 | 典型场景 | 客户端处置 |
| --- | --- | --- | --- |
| 200 | 成功 | — | — |
| 400 | 参数/契约非法 | serverKey 字符集非法;STATIC_HEADER 缺头名/头值;credentials 缺失注册;JSON 契约错 | 修请求,勿重试 |
| 401 | 鉴权失败 | embed token 缺失/过期/签名不符 | 触发宿主续签 token 后重试 |
| 403 | 授权不足 | 管理面密钥错;越权操作 | 停止重试,走权限申请 |
| 404 | 资源不存在或**无权知晓** | 非本人运行/他人 MCP 注册(行级隔离故意 404,不泄露存在性) | 视为不存在 |
| 409 | 冲突 | serverKey 在任一冲突域(应用级/宿主/用户级)被占用 | 换键 |
| 429 | 限流/并发闸 | 子 Agent 嵌套深度/并发护栏超限 | 退避重试(指数) |
| 500 | 平台内部错误 | — | 退避重试 ×N 后上报 |
| 501 | 未实现(枚举预留) | 三方 MCP `authType=OAUTH`(CIMD 流程后续批次) | 勿重试 |

> message 面向开发者(含字段级原因,如"无法解析 endpoint URL");终端用户提示由
> 宿主前端自行映射,不要直接透出原始 message。
>
> 模型档的 `ia_ai_model.max_concurrency` 目前是登记字段(压测前经 `run.sh` calibrate
> 调高以免成为吞吐瓶颈),尚未在代码中强校验为 429 拒绝位;并发容量护栏以
> `/actuator/prometheus` 的 `..._capacity_rejected_total`/`..._bulkhead_rejected_total`
> 计数为准。

## 2. 重试语义

| 操作类型 | 幂等? | 建议 |
| --- | --- | --- |
| GET(状态/列表) | 是 | 直接重试 |
| POST /runs | **否**(每次新建运行) | 失败后重试会开新运行;先查 `/runs/running` 防重复 |
| 取消/过期确认 | 幂等 | 可安全重试 |
| SSE 断线 | — | 不重发 POST,走断点续传(§3) |

## 3. 断点续传(Last-Event-ID)

**核心原则:SSE 连接断开 ≠ 运行结束。** 运行在服务端继续并把事件写入 journal;
客户端重连时:

```
GET /ia/api/v1/runs/{runId}/events
Last-Event-ID: <runId>:<最后收到的 seq>
```

服务端 **replay-then-live**:

1. 从 journal 回放 `afterSequence` 之后的所有事件(含断线期间产生的);
2. 无缝切入实时流;
3. 若运行已达终态,回放至终态事件后正常关流(客户端收到 `DONE`/`ERROR`/
   `CANCELLED` 收尾)。

客户端实现要点(参考 `tools/k6/lib/metrics.js` 的游标解析):

- 逐帧保存 `id` 的 `<seq>` 部分(数字,严格递增);
- 重连成功后可校验首帧 `seq` == 本地 seq+1(有跳号说明中间有事件,照常处理即可,
  回放保证不丢);
- 指数退避重连(如 1s/2s/5s/10s,上限 60s),避免断连风暴。

## 4. 观测:重连指标

平台侧 `ia_reconnect_total{app,result}`(IA-4):

- `result=resumed`:带游标重连且流正常追平至终态;
- `result=failed`:重连流出错;
- 纯断连(客户端 cancel/无游标)不计入。

宿主 SRE 可据此监控"用户侧断线-恢复健康度"。

## 5. 时钟与事件时间

事件 `data.createdAt` 为**服务端时钟**。做端到端延迟测量的前提:k6/客户端与
server 同机或 NTP 对齐;偏差样本应剔除并披露(平台压测口径:负偏 >250ms 判时钟
偏差,样本单独计数,见 `tools/k6/lib/metrics.js`)。
