## 3. 缺陷清单(修复由后续独立 agent 执行,本轮零产品代码改动)

### DEF-01 · P1 · web 登录页契约漂移,真服务模式无法登录
- 页面发 `{adminKey}` 占位契约,服务端要求 `{username,password}` → 400;表单无账号密码域。管理站 UI 在真服务下不可用。
- 证据:`assets/L1-09-DEF01-UI登录400错误态.png`、`L1-08-DEF01-UI登录-网络响应.json`
- 修复:见 01-认证.md(前端改 username/password + Bearer 存储与注入;文案区分 401/423)。

### DEF-02 · P1 · 工具「刷新」空体分诊污染指纹链路
- UI 刷新按钮空体调分诊 → verdict=compatible(应 unchanged),`schema_sha256` 被持久化为**空串指纹**,与 `parameters_schema` 内容脱节落库;历史留痕与授权指纹基准失真,污染 ADR-5 内核快照可复现性。管理面单键触发、静默发生。
- 证据:`assets/L3-05b-DEF02-*.json/txt`
- 修复:见 03-工具注册与分诊.md(空 schema 视为不重发走 unchanged;空值绝不覆写指纹;存量数据回填修复)。

### DEF-03 · P2 · 逻辑删工具重注册返回 200 但未复活
- `ToolRegistryService.register` 复活分支用 `updateById`,被 `@TableLogic` 附加 `WHERE deleted=false` → 对逻辑删行更新 0 行,响应 200 但库内仍 deleted → 工具永不生效且占唯一键,静默失败。
- 证据:测试迭代期间实证(register 200 后 toolIdOf=0,分诊 404;`e2e/specs/03-tools.spec.ts` 因该缺陷改物理清理)
- 修复:复活走显式 SQL(`UPDATE ... SET deleted=false WHERE id=?`,绕过逻辑删谓词)或 insert 前物理删同 FQN 死行;补一条「注销→重注册」回归用例。

### DEF-04 · P1 · 撤销后重新授予 500
- `uk_ia_tool_grant UNIQUE NULLS NOT DISTINCT(...)` 不含 deleted 谓词,逻辑删(撤销/失效)行占键;服务层查重只看活跃行 → 重授 INSERT 约束冲突 → 裸 `DataIntegrityViolationException` → 500(应 200/409)。授权生命周期核心流(可撤销可重授)断裂,SDK live-confirm 再确认同键域同样暴露。
- 证据:`assets/L5-07-DEF04-撤销后重授500.json`(revoke=200 → reGrant=500)
- 修复:见 04-授权管理.md(推荐 partial unique index `WHERE deleted=false` + GlobalExceptionHandler 把约束冲突映射 409)。

### 观察与建议(不计缺陷)
- 登录审计 `ip` 取 `X-Forwarded-For` 首值,反代场景可伪造,建议网关层清洗(记录在案)。
- `IA_ADMIN_SESSION_SECRET` 未配置时会话密钥进程内随机(server.log WARN),生产必须注入。
- 审计 `params_masked_json` 为读时脱敏,库内原文(设计取舍已实证),建议 T2 后评估写时脱敏。

## 7. T2(SDK 四线)交接注意事项

1. **环境**:直接 `source e2e/env.sh up`(compose 35432/36379 + server 18090 + gateway 18081)。SDK 线若需宿主桥:`mvn -f examples/demo-spring-host/pom.xml spring-boot:run`(18091,参考 `scripts/journey-lib.sh start_host`);真库演示数据可用 `X-IA-Demo-User` 头(anonymous demo 已开,profile=local)。
2. **mock 模型**:演示对话走 `mock-text`(platform='mock',V4 seed),脚本化驱动用 `psql` 改 `ia_ai_model.config`(参考 `journey-lib.sh set_mock_script`);确认卡四档验证用「写操作 + mock 脚本驱动工具调用」。
3. **登录态**:SDK 线不依赖管理站登录;如需管理面断言用 `X-IA-Admin-Key: test-key`(自动化通道)。
4. **Playwright 1.63 陷阱(必读)**:用例失败后 worker 以**新模块实例**继续,模块级随机常量跨用例变化(已用探针实验证实)。T2 的 spec 必须沿用本套固定标识符 + 每用例自建前置模式(`helpers/support.ts` 的 `psql/toolIdOf` 式现查库),不要跨用例共享 `let` 状态。
5. **可复跑铁律**:自建数据物理清理(psql DELETE),**不要**只做逻辑删——DEF-03(重注册不复活)与 DEF-04(重授 500)在逻辑删残留上必炸。
6. **Element Plus locale**:断言确认框按钮时用 `helpers/support.ts confirmBox`(自定义文案中文、默认英文 OK);分页 total 是英文 "Total N"。
7. **已知服务端缺陷前置**:DEF-02(空体分诊)意味着**不要**用 UI「刷新」按钮做断流/快照相关断言的触发器;DEF-04 意味着授权重复授予场景只能物理清理后重建。
8. **SSE 断言**:gateway.mjs 的 `/ia` 反代支持流式(透传 chunked);事件持久化 ID 形如 `runId:seq`,终态 `outputType ∈ DONE/ERROR/CANCELLED/USER_CONFIRMATION_REQUIRED`(参考 `scripts/journey-lib.sh` 的 wait_terminal/wait_pause/sse_extract)。
9. **报告衔接**:T2 报告建议落 `test-report/2026-09-21-02/`,复用 assets 命名规范(`L<线>-<序>-<描述>.png` + API 证据 JSON/txt),与本分册缺陷编号(DEF-xx)连续编号。

## 附录:本轮方法论教训(供 T2 复用)

- **失败后模块重求值**:探针实验(zz-probe)证实失败用例会使后续用例拿到全新模块实例 —— 一切「跨用例内存状态」都是定时炸弹;
- **el-table 固定列克隆**:行定位必须加 `visible=true`,且客户端分页会把手标行挤到第 2 页 —— 断言前先按关键字过滤;
- **psql -tA 布尔输出是 t/f**,不是 true/false;
- **Element Plus el-radio-button**:真实 radio input 不可点,点 `.el-radio-button` 文本容器。
